# 12 · 给 v3（Rust 求解器）的接入说明

> 本文属于 `documents/`（**文档**目录）。读者 = **ArknightsInfraCalc-v3** 侧的实现者。
>
> **一句话**：v3 把求解出来的**高效基建布局**交给本项目（Rhodes-MoodSOC），本项目负责
> 生成它的**完整心情变化周期**，然后回答两个问题：
>
> 1. **「某人 + 时间节点」→ 她的心情（和她在哪）**；
> 2. **「时间节点」→ 整座基地的布局 + 全员心情**。
>
> 线协议、逐 op 字段表、错误形状在 `11-程序接口.md`；本文只讲**怎么接、按什么顺序调、默认口径是什么**。

---

## 1. 责任边界（别把两份心情模型搅在一起）

| 谁 | 算什么 | 不做什么 |
|---|---|---|
| **v3** | 设施机制 / 技能效率 / 产出 / 订单 / 无人机；**排谁进哪间房**（含轮换） | 不算"这套布局能连续跑几轮" |
| **本项目** | 心情电池（消耗 / 回复 / 红脸）、**整周期心情轨迹**、闲置入宿、进驻事件（M15a 换心情） | 不选干员、不算效率、不改 v3 的求解结果 |

本项目**只读** v3 给的布局与配置；它内部会为模拟深拷贝一份布局副本（换人只改副本），
**绝不回写**你的排班。需要拿回排班时用 `export_schedule`（导回本工具场景 JSON）。

---

## 2. 起一个常驻进程

```bash
python -m api.server --quiet          # stdin/stdout = NDJSON（一行一请求、一行一响应）
```

- **优先用常驻**：`data/skills_data.py`（755 条 buff 的对象图）import 一次 0.3~0.5s，
  一次性调用每次都要付这笔钱。之后每次 `moods` ≈ 重算一轮（周期 1 约 0.2s、周期 3 约 0.7s）。
- 仓库根用**环境变量**传（如 `RHODES_MOODSOC_ROOT`），别硬编码；`current_dir` 指过去即可。
- 解释器建议用仓库自带的 `.venv/Scripts/python.exe`（纯标准库，无第三方依赖）。
- `stderr` **别丢**：`--quiet` 时基本安静，但"哪个 op 为什么失败"只在 stderr 上。

## 3. 先握手

```jsonc
{"id": 1, "op": "capabilities"}
// ← {"id":1,"op":"capabilities","ok":true,"protocol":2,
//    "data":{"protocol":2,"operations":[…36 个…],"stateful":true,"loaded":false,"docs":"documents/11-程序接口.md"}}
```

**`protocol` 必须等于 2**，不一致就报错退出——否则双方会悄悄按不同语义算。
（协议版本在增删 op / 改字段语义时 +1；本项目 `api/__init__.py:PROTOCOL_VERSION`。）

## 4. 一次完整调用（照抄即可）

假设 v3 的 `plan.compute` 已经把结果拿到手（就是 serve 那条响应里的 `result` 或整个响应信封）。

```jsonc
// ① 把求解结果原样喂进来（内联，不落临时文件）
{"id": 10, "op": "load_json", "args": {
   "data": { /* v3 的 serve 响应 {"id":…,"ok":true,"result":{…}} 或直接 result 对象 */ },
   "apply_file_settings": false,     // 默认就是 false：不继承文件里的 Fiammetta 开关
   "idle_to_dorm": true,             // 默认就是 true：按本项目默认四级优先级
   "cycles": 1                       // 默认 1 ＝ 正好一个完整周期（12/6/6 → 24h）
}}
```
```jsonc
// ② 想开「换干员」（进驻事件 M15a）才需要这一步；不开就跳过
{"id": 11, "op": "set_entry_events", "args": {
   "enabled": true,
   "swap_with": null,                // null = 同宿舍「前一位进驻」；人名 = 指定；"any" = 全基建最累的
   "scope": "dorm",                  // "dorm"（默认）或 "anywhere"
   "when": "immediate",              // "immediate" 立刻 / "wait" 等她回满 / "full" 只在她满心情时
   "per_shift": [{"key": 1, "enabled": true, "swap_with": "巫恋"}]   // 按班次覆盖（可选）
}}
```
```jsonc
// ③ 想改「闲置入宿」口径才需要（默认已开、全自动）；逐人/逐次设置走 per_operator
{"id": 12, "op": "set_idle_to_dorm", "args": {
   "enabled": true,
   "per_operator": [{"name": "某人", "enabled": false}]      // 让某人不参与
}}
```
```jsonc
// ④ 想改「周期配置」才需要（默认取文件里的各班时长）
{"id": 13, "op": "set_timeline", "args": {
   "hours": [12, 6, 6],              // 各班时长（长度必须 == 班次数；改完周期 = 之和）
   "cycles": 1,                      // 连跑几个周期
   "start_clock": 0                  // 周期起点是几点（**纯显示口径**，引擎数值不变）
}}
```

### 查询 A：某人 + 时间节点 → 心情

```jsonc
{"id": 20, "op": "operator_detail", "args": {"name": "但书", "at": 8}}
// ← {"name":"但书","in_base":true,"detached":false,"facility":"贸易站#1",
//    "elite":2,"level":30,"skills_unlocked":6,"skills_locked":[],
//    "mood":22.4,"rate":0.85,"red_face_spans":[]}
```
`at` 两种写法：`8`（**绝对小时**，跨周期递增）/ `"08:30"`（**周期内**钟点）。
不在基建的人也查得到（`in_base:false`、`facility:null`、速率 0、心情恒定）。

### 查询 B：时间节点 → 整座基地的布局 + 全员心情

```jsonc
{"id": 21, "op": "layout_at", "args": {"at": 8}}
// ← 见 11-程序接口.md §6.1：rooms[]（每间房 + 位次 + 在位干员 + 心情/速率）+ detached + moods
```

### 附：闭环体检（这套布局能不能长期跑）

```jsonc
{"id": 22, "op": "closure", "args": {"cycles": 3}}
// ← {"converged":true,"converged_from_cycle":2,"layout_sustain_hours":21.5,
//    "bottleneck":"泡泡","delta_last_vs_first":{…},"verdict":"稳定但有人红脸：…"}
```
⚠️ `closure` **会改会话的 `cycles` 并重算**（口径同 `moods` 的 `cycles` 参数）；
用完要么接着按这个周期数用，要么再 `set_timeline {"cycles": 1}` 改回去。

## 5. v3 有什么 → 本项目收什么

| v3 侧 | 本项目 | 落点 |
|---|---|---|
| `plan.compute` 的结果（`rotation.shifts[].assignment.rooms[]` / `maa.plans[].rooms` / `layout.rooms[].kind,level`） | 排班（房间 / 等级 / 人员 / 练度） | `load_json.data`（**格式自动识别**，含 `{"result": …}` 信封） |
| `rotation.shifts[].duration_hours` | 各班时长 → 周期 | 自动读；要覆盖才传 `hours` |
| `options.fiammetta_enable` / `plans[].Fiammetta` | 「换心情」（进驻事件 M15a） | **默认不继承**；要开走 `set_entry_events` |
| 轮换里的休息队（`dormitory` 段） | 宿舍进驻（本来就在排班里） | 自动读 |
| 没排到班的干员（box 里其余人） | 「闲置入宿」候选 | **默认开**（本项目四级优先级） |
| `layout.dorm_beds` / `dorm_ambience_level` | 宿舍床位 / 氛围 | 自动读（v4 蓝图格式） |
| `layout.scenario.initial_global` | 变量初始值（人间烟火 / 感知信息 …） | 自动读（映射表见 `store/sources.py:GLOBAL_RESOURCE_MAP`） |
| 求解器参数 `top` / `system_preferences` / `weighted_*` / `efficiencies` / `drones` / `product` | 与心情无关 | **忽略**，并写进 `import_report` |

## 6. 默认口径（**已按用户裁决固定，别改**）

| 项 | 默认 | 怎么改 |
|---|---|---|
| **换干员**（进驻事件 M15a） | **关**（且不继承文件里的 `Fiammetta.enable`） | `set_entry_events {"enabled": true, …}` |
| **闲置入宿** | **开**，用本项目默认四级优先级 | `set_idle_to_dorm {"enabled": false}` 或逐人 `per_operator` |
| **周期** | 取 v3 给的各班时长之和（`12/6/6` → 24h），`cycles = 1` | `set_timeline {"hours": […], "cycles": n}` |
| 周期起点心情 | 布局里写的值（没写就是满心情 24） | `set_moods {"moods": {"全部": 24}}` |
| 练度 | 满练（E2 / 等级 30） | `set_training {"elite": 1, "names": […], "level": 30}` |

> 闲置入宿的"默认开"**只作用于 `load_json` 这个入口**；界面与 `load_file` 仍维持原默认（关），
> 所以 v3 接进来的行为不会和既有的界面使用混在一起。

---

## 7. 容易踩的坑（都在本项目踩过）

1. **协议版本**：`capabilities.data.protocol != 2` 就别继续（本项目 `PROTOCOL_VERSION = 2`）。
2. **调用顺序有状态**：一次进程 = 一个 `Session`；
   `load_json`/`load_file` 会**重置**会话（起点心情、锚点、设置全部重读），
   所以顺序永远是 `load_*` → `set_*` → 查询。
3. **未载入就查询** → `error.type = "bad_request"`、message 里写清"先调 load_json"。
4. **格式认不出** → `bad_request`，message 会列出顶层键；别自己猜是哪种格式。
5. **`start_clock` 只改显示**：`"08:30"` 这种钟点写法按"周期内时刻"换算，与它无关。
6. **`moods` / `closure` 的 `cycles` 参数会改会话状态**（不是临时值），改了就留着。
7. **`layout_at` 读的是引擎副本**：换心情 / 闲置入宿换过人之后的**真实**排布，
   与 `export_schedule`（你给进来的排班快照）在换过人后必然不同——问"她现在在哪"用 `layout_at`。
8. **别把 stderr 丢掉**；也别指望 stdout 出错误（错误永远不走 stdout，退出码 1）。

---

## 8. 不用常驻进程的替代做法

```bash
# 内联 JSON 一把过：载入 → 查某人 → 查整座基地
python -m api.cli --op load_json --args @plan_result.json \
  --then '{"op":"operator_detail","args":{"name":"但书","at":8}}' \
  --then '{"op":"layout_at","args":{"at":8}}'
```
成功 = 最后一步的结果打到 stdout；失败 = 错误对象打到 stderr 且退出码 1。

  --args @resources/import_v3_out_3shifts.json \
  --then '{"op":"layout_at","args":{"at":8}}' \

v3 侧验收口径：**同一份求解结果**，经本项目算出的"某时刻全员心情"必须与
`layout_at` 里逐人的 `mood` **逐位相同**（两处是同一份轨迹，见 `11-程序接口.md` §1）。
