# 08 · 程序接口（`api/`）

> 本文（`documents/` 下的 `08-程序接口.md`）：`api/` 把图形界面能做的事**全部**暴露成「JSON 进 / JSON 出」，
> 供外部程序（主要是 Rust 侧求解器）调用，**不依赖 tkinter**。状态在 `store/session.py`，计算在
> `mood_soc/`，数据在 `data/`。

## 1. 为什么要它 / 边界在哪

`ui` 与 `api` **互不 import**（`tests/test_layers.py` 盯着），两边都只经 `store.Session` 与 `mood_soc`
的公开 API 做事 —— `ui/app.py`（tkinter 视图）与 `api/ops.py`（38 个 op）共用同一个 `Session`：

```
        ui/app.py（tkinter 视图）        api/ops.py（38 个 op）
                 │                              │
                 └──────── store/session.py ────┘   ← 状态与重算的唯一住处
                                   │
                    mood_soc/（纯计算） + data/（数据）
```

所以「界面 8.4、API 9.1」这种分叉不可能出现（`tests/test_api_ops.py::Test数值同源` 还逐位比对）。

## 2. 两种用法

### 2.1 常驻进程（**推荐**）

```bash
python -m api.server            # stdin/stdout 都是 NDJSON；stderr 是日志
python -m api.server --quiet
```

`data/skills_data.py`（755 条 buff / 250 条 clause）import 一次约 **0.3~0.5 s**，常驻只付一次；之后每次
`moods` ≈ 重算一轮（周期 1 约 0.2 s、周期 3 约 0.7 s）。

```jsonc
// stdin（一行一条）
{"id": 1, "op": "capabilities"}
{"id": 2, "op": "moods", "args": {"at": [0, 8, "24:00"], "include_trajectory": true}}
{"id": 3, "op": "quit"}

// stdout（一行一条，与请求同序）：每条都带 op / ok / protocol / id
{"op":"capabilities","ok":true,"protocol":5,"id":1,"data":{...}}
```

**会话是有状态的**：一次进程 = 一个 `Session`，`load_*` 会**重置**会话（起点心情、锚点、设置全部重读），
顺序永远是 `capabilities → load_json / load_schedule / load_file → set_* → moods / layout_at / closure`。

### 2.2 一次性调用

```bash
python -m api.cli --op capabilities

# 内联布局 → 所有干员心情（此刻 + 8h + 周期末 + 曲线 + 红脸 + 瓶颈）
python -m api.cli --op load_schedule \
  --args '{"facilities":[{"type":"制造站","level":3,"operators":["泡泡","黍","路人甲"]}]}' \
  --then '{"op":"moods","args":{"at":[0,8,"24:00"],"include_trajectory":true}}'

cat req.json | python -m api.cli --op moods --args @-        # args 从管道读；`--then` 可串多步
```

`--args` 三种写法：内联 JSON / `@文件` / `@-`（stdin）。成功 = 最后一步的结果打到 **stdout**；
失败 = 协议错误对象打到 **stderr** 且退出码 1（`moods=$(python -m api.cli ...)` 因此不会把错误当数据）。

## 3. 线协议（**稳定面**）

| 请求字段 | 必填 | 说明 |
|---|---|---|
| `op` | ✓ | 操作名，见 §4 |
| `args` | | 该操作的参数对象（缺省 `{}`） |
| `id` | | 原样回显，便于调用方配对（任意 JSON 值） |

| 响应字段 | 说明 |
|---|---|
| `id` / `op` | 与请求相同（`id` 缺省则不回填） |
| `ok` | `true` 成功 / `false` 失败 |
| `protocol` | 协议版本号，**每个响应都带**（长连接里随时能发现版本漂移） |
| `data` | 成功时的结果 |
| `error` | 失败时的 `{"type","message"}` |

**错误类型**：参数类问题（`ValueError` / `KeyError` / `TypeError`）→ `"bad_request"`，其余异常用类名。
**任何 op 出错都不会杀掉常驻进程**，下一条请求照常处理（坏 JSON 也一样，回一条 `op: null` 的错误响应）。

**先握手**：

```jsonc
{"id": 1, "op": "capabilities"}
// → data = {"protocol": 5, "operations": [38 个 op 名], "stateful": true, "loaded": false,
//           "docs": "documents/08-程序接口.md"}
```

`protocol` 与预期不一致就**别继续**——否则双方会悄悄按不同语义算。协议改动（增删 op、改字段语义）时
`api/__init__.py` 的 `PROTOCOL_VERSION` 加一；当前为 5（**4 → 5（2026-10）**：新增 `set_seat_lock` /
`clear_seat_locks`，并给 `set_slots` 加 `manual`）。握手请求可在 `args.expected_protocol` 声明调用方版本，
不符则返回 `error.type = "protocol_mismatch"`（附 `expected` 与 `actual`）并拒绝按该版本执行。

**时刻的两种写法**（所有带时刻的 op 通用）：**绝对小时** `0` / `8.5` / `"36"`（从周期起点算起，跨周期递增）；
**钟点字符串** `"08:30"` / `"1:05"` / `"24:00"`（**周期内**时刻，`"24:00"` = 周期末，与界面时刻标签同义）。
⚠️ `start_clock`（初始时间点）只影响**显示**。

### 载入（4）

| op | 作用 | 关键参数 |
|---|---|---|
| `load_schedule` | **内联布局** → 单班排班（最常用）。⚠️ 带**已撤**的键（如 `per_operator`）时，返回体里会**多一个 `notes` 键**（additive：不带就没有这个键） | `facilities`✓、`hours`、`label`、`entry_events`、`idle_to_dorm`、`initial_global` |
| **`load_json`** | **内联 JSON**（任意受支持格式，含 v3 求解输出）→ 排班；**不落临时文件** | `data`✓、`hours`、`cycle_hours`、`cycles`、`apply_file_settings`、`entry_events`、`idle_to_dorm` |
| `load_file` | 按**一个文件**载入（4 种格式自动识别） | `path`✓ |
| `load_files` | 按**多文件**载入（12h / 6h / 6h 三个那种） | `paths`✓ |

`facilities` 元素与场景 JSON 同构：
`{"type": "制造站", "level": 3, "name": "制造站#1", "operators": [...], "deputies": [...], "enabled": true}`；
干员可以是名字或 `{"name","mood","elite","level","skill_ids","factions"}` 对象；顶层还可带 `entry_events` /
`idle_to_dorm` / `initial_global` / `detached`。⚠️ `load_*` 的**同名顶层参数**优先于文件里的同名字段；文件里
那个 `idle_to_dorm` 在**按文件导入**那条路（界面 / `load_file`）**一定生效**
（`{"enabled": false, "protected_slots": 2, "blacklist": ["甲"]}` 真的读进来，解析只有
`models.build_idle_to_dorm_config` 一处）。见 §15。

**`load_json` 的默认口径**（比界面 / `load_file` 收窄）：文件里的开关（如 v3 的 `Fiammetta.enable`）**不继承**
（`apply_file_settings: false`）；闲置入宿**开**（`idle_to_dorm: false` 关掉）；换心情**关**（`entry_events: true`
才结算）；周期取文件里的班次时长之和（如 `12/6/6` → 24h，`cycles` 默认 1）。规则见 `03-特殊机制.md`
第 30 条，完整口径表见 §15。它与 `load_file` 走**同一条装配路径**
（`store.schedule.load_schedule_from_imports`），数值**逐位相同**（`tests/test_api_ops.py::Test求解器适配` 盯着）。

### 编辑（16）

| op | 作用 | 关键参数 |
|---|---|---|
| `set_timeline` | 各班长 / 周期校验 / 周期数（1~`MAX_CYCLES`＝7，越界夹取）/ 初始时间点 | `hours`、`cycle_hours`、`cycles`、`start_clock` |

| **`set_detached`** | **「不在基建」名单**：整份替换 / 增量增删 / 顺便设起点心情 | `names`、`add`/`remove`、`moods`、`remove_from_slots` |
| `set_initial_moods` | 整份替换**周期起点**心情（`{}` = 回导入值） | `moods`✓（支持 `{"全部": 24}`） |
| `set_moods` | `set_initial_moods` 的别名 | 同上 |
| `set_mood_at` | **指定时刻**把某人心情置为给定值（锚点 / 同刻跳变） | `name`✓、`mood`✓、`at` |
| `clear_mood_events` | 清空全部锚点（不动起点心情） | — |
| `restore_imported_moods` | 「恢复导入值」：清起点心情 + 清全部锚点 | — |

| `set_entry_events` | 「换心情」（M15a）：开关 / 换谁 / 范围 / 时机 / 按班次覆盖 | `enabled`、`swap_with`、`scope`、`when`、`per_shift` |

|---|---|---|

### 不在基建：一次完整调用

```bash
# 把"这一刻没上班、也不在宿舍"的人列出来，并给其中一个设心情 12
python -m api.cli --op load_file --args '{"path":"resources/arknights-infra-schedule-maa.json"}' \
  --then '{"op":"bench_names","args":{"shift_index":1}}' \
  --then '{"op":"set_detached","args":{"add":["某人"],"moods":{"某人":12}}}' \
  --then '{"op":"moods","args":{"at":[0,12]}}'
```

```jsonc
// bench_names → data（detached = 名单点名的 ∪ 整个排班都没排到位置的；explicit = 名单里显式写的）
{"detached": ["歌蕾蒂娅", "寒芒克洛丝"], "explicit": ["歌蕾蒂娅"], "stationed": ["泡泡", "黍"],
 "shift_index": 1, "not_in_shift": ["歌蕾蒂娅", "寒芒克洛丝"]}
```

⚠️ `add` 默认 `remove_from_slots: true` —— 加进名单时会把她**从所有班次的位置上摘掉**
（「名单里的人 ↔ 不在任何房间里」是一条不变式）；要保留位置就传 `remove_from_slots: false`。

## 5. `moods` 的返回（核心输出）

```jsonc
{
  "operators": ["泡泡", "黍", "路人甲", "板凳甲"],
  "cycle_hours": 24, "cycles": 2, "total_hours": 48,
  "moods": {"0": {"泡泡": 24, "黍": 24, "路人甲": 24, "板凳甲": 12}, "24": {"泡泡": 19.2, ...}},
                                   // 键 = 绝对小时；值是"那一刻的全员心情"
  "trajectory": {                  // include_trajectory=true 才有
    "times": [0, 0.25, 0.5, ...],  // 节点即"事件时刻"（见 07-图形界面.md §4.1）
    "operators": {"泡泡": [24, 23.99, ...], "板凳甲": [12, 12, 12, ...]}
  },
  "red_face": {"泡泡": [[21.0, 24.0]]},   // 有红脸段才出现
  "layout_sustain_hours": 21,      // 第一个人红脸的时刻（null = 整段没人红脸）
  "bottleneck": "泡泡"
}
```

数值口径：**6 位小数**舍入、`inf → null`（见 `store/serialize.py`）。轨迹节点是"速率会变的时刻"（班次边界 /
红脸 / 心情阈值 / 两人交叉），节点之间**严格线性**，按线性插值取值与引擎结果一致。**「不在基建」的人**
（`set_detached` / 场景顶层 `detached`）也在 `operators` / `moods` / `trajectory` 里，数列是**一条平线**
（＝起点心情，速率 0），且**不参与任何技能计数**。

## 6. `layout_at` / `closure` 的返回

### 6.1 `layout_at`：时间节点 → 整座基地

```jsonc
{"at": 8, "cycle": 1, "in_cycle": 8, "shift_index": 1, "shift_label": "1. alpha/beta · 12h",
 "rooms": [                        // 房间顺序 = 布局顺序（未排序），索引 1 基、位次 1 基
   {"index": 1, "type": "贸易站", "name": "贸易站#1", "level": 3, "capacity": 3, "enabled": true,
    "operators": [{"slot": 1, "name": "但书", "mood": 22.4, "rate": 0.85, "elite": 2, "level": 30}],
    "deputies": []},               // 副手（不占位、不消耗心情）
   ...],
 "detached": [{"name": "歌蕾蒂娅", "mood": 24, "rate": 0}],   // 不在基建：心情一条平线
 "moods": {"但书": 22.4, "歌蕾蒂娅": 24, ...}}
```

⚠️ **读的是引擎那份布局副本**（`Trajectory.world_at`）——换心情 / 闲置入宿换过人之后的**真实**排布，
**不是**你导入的那份快照（`AGENTS.md` 第 20 条那个坑）。落在班次边界取**右侧**。

### 6.2 `closure`：这套布局能不能长期跑

```jsonc
{"cycles": 3, "cycle_hours": 24,
 "cycle_start_moods": {"1": {"泡泡": 24, ...}},           // 第 1 周期起点
 "cycle_end_moods": {"1": {...}, "2": {...}, "3": {...}}, // 每个周期末（＝下一轮开局）
 "converged": true, "converged_from_cycle": 2,            // 第 2 与第 3 周期末逐人相同
 "delta_last_vs_first": {"泡泡": 0, ...},                 // 周期末 − 周期初（<0 = 越跑越累）
 "layout_sustain_hours": 21.5, "bottleneck": "泡泡",      // null = 整段没人红脸
 "red_face": {"泡泡": [[21.5, 24.0]]},
 "verdict": "稳定但有人红脸：第 2 周期起周期末不再变化，但 泡泡 在 21.5h 就红了脸"}
```

口径：`cycles` 是**心情跨周期连续**（`simulate_schedule` 的同一语义），"周期末"即下一轮的开局心情；相邻两
周期的周期末逐人相同（容差 1e-9）即认定进入固定点。⚠️ 这个 op **会改会话的 `cycles` 并重算**。

## 7. Rust 侧怎么接

常驻 + 一次握手 + 一次调用（最小可用）：

```rust
use std::io::{BufRead, BufReader, Write};
use std::process::{Command, Stdio};

fn main() -> std::io::Result<()> {
    let mut child = Command::new("python")
        .args(["-m", "api.server", "--quiet"])
        .current_dir(std::env::var("RHODES_MOODSOC_ROOT").unwrap())
        .stdin(Stdio::piped()).stdout(Stdio::piped()).stderr(Stdio::inherit())
        .spawn()?;
    let (mut stdin, mut out) = (child.stdin.take().unwrap(),
                                BufReader::new(child.stdout.take().unwrap()));
    let mut call = |line: &str| {                     // 一行请求 → 一行响应
        writeln!(stdin, "{line}").unwrap(); stdin.flush().unwrap();
        let mut s = String::new(); out.read_line(&mut s).unwrap(); s
    };

    let caps: serde_json::Value = serde_json::from_str(&call(r#"{"id":1,"op":"capabilities"}"#)).unwrap();
    assert_eq!(caps["data"]["protocol"], 5);         // 版本不一致就别继续
    call(r#"{"id":2,"op":"load_json","args":{"data":{ ... }}}"#);   // v3 结果原样塞进来，不落文件
    println!("{}", call(r#"{"id":3,"op":"moods","args":{"at":[0,8,24]}}"#));   // 结果就是那一行响应信封
    call(r#"{"op":"quit"}"#);
    let _ = child.wait()?;
    Ok(())
}
```

三条经验：**路径别硬编码**（环境变量如 `RHODES_MOODSOC_ROOT` 传仓库根，`current_dir` 指过去即可）；
**每行 flush**（服务端已做 `stdout.flush()`，Rust 侧 `read_line` 不会卡）；**别把 stderr 丢掉**
（`--quiet` 时出错信息只在 stderr 上，`Stdio::inherit()` 或自己收着都行）。不想管进程生命周期时用一次性
CLI（`Command::output()` 收结果，错误走 stderr），见 §17。

## 8. 加一个新 op 的步骤

1. 在 `api/ops.py` 写 `def op_xxx(session, args) -> dict`：
   **只做"取参 → 改 Session → 返回结果"**，不自己存状态、不算心情；
   参数用 JSON 原生类型，进来就 `to_decimal()`；数值出参一律过 `_num()`；
2. 加进 `OPERATIONS` 表（表就是契约，`capabilities` 会报给调用方）；
3. 在 `tests/test_api_ops.py` 里加一条黑盒断言（走 `handle(...)`，别直接调 Session）；
4. 若改变了已有 op 的语义 / 删了 op → `api/__init__.py` 的 `PROTOCOL_VERSION` +1；
5. 更新本文 §4 的表格。

**不许**在 `api/` 里 import `ui` / `tkinter`（`tests/test_layers.py` 会报错）。

> `apply_idle_to_dorm` 都默认结算，只有**显式关**（`{"enabled": false}` / 取消勾选 / `idle_to_dorm=False` /

> 班内每个**严格小于班末**的 12h 整数倍都是**内部换班执行点**（位置按该班原始布局重建、进驻事件与闲置入宿
> 重跑，并记一条 `internal` 标记）。
> ⚠️ **文件顶层真写了 `idle_to_dorm` 时两个入口口径不同**（有意）：**导入层一定认得它**（`{"enabled": false, …}` /
> `protected_slots` / `blacklist` 都生效，解析只有 `models.build_idle_to_dorm_config` 一处），
> 所以界面 / `load_file` **会**读出那个开关；`load_json` / `load_layout` 缺省**覆盖**它（缺省＝开）。

## 16. 容易踩的坑（都在本项目踩过）

1. **协议版本**：`capabilities.data.protocol != 5` 就别继续（本项目 `PROTOCOL_VERSION = 5`）；也可在握手请求
   里传 `args.expected_protocol: 5`，旧版本会收到 `protocol_mismatch`，不得继续调用（协议改动史见 §3）。
2. **调用顺序有状态**：一次进程 = 一个 `Session`；`load_json`/`load_file` 会**重置**会话，所以顺序永远是
   `load_*` → `set_*` → 查询。
3. **未载入就查询** → `error.type = "bad_request"`，message 里写清"先调 load_json"。
4. **格式认不出** → `bad_request`，message 列出顶层键；别自己猜是哪种格式。
5. **`start_clock` 只改显示**：`"08:30"` 这种钟点写法按"周期内时刻"换算，与它无关。
6. **`moods` / `closure` 的 `cycles` 参数会改会话状态**（不是临时值），改了就留着。
7. **`layout_at` 读的是引擎副本**：换心情 / 闲置入宿换过人之后的**真实**排布，与 `export_schedule`（你给进来的
   快照）在换过人后必然不同——问"她现在在哪"用 `layout_at`。⚠️ `rooms[].name` **现在带序号**
   （`"宿舍"` → `"宿舍#1"`，`index` 仍是 1 基的布局顺序）：未命名设施自动补名 `{类型标签}#{同类型序号}`
   （**只写模型对象、导出不变**），好让锁定区 / 手动锁的稳定键 `(类型, 实例名)` 永远成立。
8. **锁定入宿（把某人钉在某个位次）必须写 `facilities[].manual`** —— 只写 `slots` **不上锁**，自动入宿会把她
   换走。⚠️ **2026-10 口径反转**：手动编辑是 **「摆位即上锁、清空即解锁」**—— `manual.slots` 只含**摆了人的
   位次**（被清空的位次**不在里面**，＝交还自动入宿）、`manual.names` = 人放的干员（连人一起钉住）。逐字可抄
   （`slots` 里的 `null` = 该位留空）：
   `{"type": "宿舍", "level": 5, "slots": ["甲", null, "乙"], "manual": {"slots": [0, 2], "names": ["甲", "乙"]}}`。
   也可以走 op：`set_slots {"manual": true}`（默认 true；**写空串＝解锁那一位**）或逐位
   `set_seat_lock {"shift_index": 1, "facility_index": 4, "slot": 2, "locked": true}`（**界面已经不用它了**，
   但 API 保留）；**整份交还**用 `clear_seat_locks`（返回 `{"cleared_shifts": n}`）。
9. **别把 stderr 丢掉**；也别指望 stdout 出错误（错误永远不走 stdout，退出码 1）。

## 17. 不用常驻进程的替代做法

`load_json` 的 `data` 就是**整个求解结果**，要包一层 `{"data": …}` 再交给 `--args`：

```bash
# ① 包一层（v3 的结果文件 result.json → 请求文件 req.json）
python -c "import json;d=json.load(open('result.json',encoding='utf-8'));json.dump({'data':d},open('req.json','w',encoding='utf-8'),ensure_ascii=False)"

# ② 一把过：载入 → 查某人 → 查整座基地
python -m api.cli --op load_json --args @req.json \
  --then '{"op":"operator_detail","args":{"name":"但书","at":8}}' \
  --then '{"op":"layout_at","args":{"at":8}}'
```
成功 = 最后一步的结果打到 stdout；失败 = 错误对象打到 stderr 且退出码 1。想直接喂一个文件的**路径**时用
`load_file`（`--args '{"path":"…"}'`），它按 4 种格式自动识别——但那要先落盘；Rust 侧在内存里就用 `load_json`。

## 18. 接了以后怎么自测

```bash

  --args '{"path":"resources/import_v3_out_3shifts.json"}' \
```

v3 侧验收口径：**同一份求解结果**，经本项目算出的"某时刻全员心情"必须与 §6.1 `layout_at` 里逐人的
`mood` **逐位相同**（两处是同一份轨迹，同源关系见 §1）。
