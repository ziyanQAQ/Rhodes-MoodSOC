# 干员信息规范

## 1. 定位

干员信息是静态数据与运行时名册的边界。静态目录描述干员身份和基建技能；名册描述本次模拟中哪些干员可参与，以及其练度、初始心情和班次关系。

## 2. 稳定字段

| 字段 | 含义 | 约束 |
|---|---|---|
| `operatorId` | 稳定内部 ID | 不得用显示名替代 |
| `name` | 默认显示名 | 可本地化，不参与业务关联 |
| `aliases` | 外部名称/旧名称 | 仅用于导入适配 |
| `factions` | 阵营集合 | 由数据目录维护 |
| `skills` | 基建技能引用 | 只引用已注册技能 |
| `elite` / `level` | 练度 | 缺失时按明确默认值并生成警告 |
| `initialMood` | 本次模拟起始心情 | 运行时字段，范围 `[0,24]` |

## 3. 规则关联

技能必须通过 `operatorId → skillId → clause/template` 关联。领域层不得写“某干员名称特判”；特殊机制应表现为技能数据、条件策略或事件策略。未知干员、未知技能或缺失关键练度默认是错误，不得静默当作无技能。

## 4. 数据来源与生成

游戏事实优先使用可追溯的一手上游数据；项目文档记录建模解释和不支持项。原始数据、规范化目录、运行时索引分离，生成物禁止手改。每次更新记录上游版本、生成器版本、覆盖范围和未支持技能。

当前首版目录由 `ArknightsGameData/zh_CN/gamedata/excel/building_data.json` 与 `character_table.json` 生成，具体输入 SHA-256、生成时间和覆盖数量以 `data/generated/manifest.json` 为准。当前归档生成 432 名有基建数据的干员；这不是全角色数量，也不代表所有角色都具备已建模的基建技能。

当前 schema 2 保留 `skillUnlocks` 的精英阶段、等级、组号和逻辑来源路径；不将同组候选解释为全部同时生效。
`factionLinks` 分别保留 nation/group/team 来源，显示名取自 `handbook_team_table.json`。
`factions.json` 只记录目录内的直接成员关联，不等同于技能要求的成员集合，格式与校验见 [`施工/01-data层施工.md`](施工/01-data层施工.md)。

## 5. 名册语义

名册包含导入过、被清空或被自动换出的干员，保证曲线和设置查询不会因当前布局为空而丢失干员。`detached` 只表示原始布局未占用设施，不表示禁止自动入宿；禁止自动进入宿舍使用黑名单。

## 6. 验收

同一 `operatorId` 在不同显示语言、班次和布局副本中必须保持身份一致。导入别名只能在适配器中解析，进入领域层后统一使用稳定 ID。
