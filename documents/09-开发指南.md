## 维护约定（必读）

1. **改完要同步文档**。代码 / 数据 / 文档 / 结构 / 数值规则任一改动后，至少更新：
   - 根目录 `README.md`（人类入口）与 `AGENTS.md`（AI 入口）；
   - `documents/` 下**受影响的**那一篇（改数值 → `02-数值规则.md`；加机制 → `04-特殊机制.md`；
     加模板 → `05-技能分类大纲.md`；换数据来源 → `06-数据来源.md`）。
   别让文档和代码分叉——分叉的文档比没有文档更危险。

2. **提交约定**：每完成一次修改就**立即 `git commit` 一次**，不要攒着；
   提交信息用 **1–15 个字**简要描述（如「修复替换链」「补变量账本」「忽略 IDE 目录」），
   不写多段说明、不加 `feat:`/`fix:` 前缀。一次提交只做一件事
   （改了代码就别把无关文档混进来，除非该文档是这次改动的同步更新）。

3. **文档按门类分文件、别堆成一个大文件**。一个门类一件事，文件名即主题；
   跨文档引用用 `§编号`（稳定 ID，映射表见 `documents/README.md`），
   或者直接写 `<文件名>.md`。

4. **根 `AGENTS.md` 保持精简**。它有 **65536 字节指令预算**，超了会被**截断**、
   尾部对读的人/AI 不可见——"读不到的文档等于不存在"。
   细节写进 `documents/` 对应门类，`AGENTS.md` 里只留一行指针。
   新增内容前先自查：`(Get-Item AGENTS.md).Length`（当前约 7.8KB，余量充足）。

5. **上游数据优先**：任何"不知道的数据"先去上游仓库查证，不要猜、不要从二手资料誊抄——
   完整策略见 `06-数据来源.md`。

## 9.5 性能基线（改完"算得更多"的东西就回来量一遍）

**唯一的瓶颈是引擎重算**（`store.session.Session.recompute()`）；渲染层可以忽略：
`session.idle_groups()` 6.8ms、`ui/app.py:_build_shift_buttons()` 5.4ms、`traj.world_at()` 0ms、
`layout_at(t)` 0.24ms、`moods_at(t)` 0.06ms。

示例排班（`resources/arknights-infra-schedule-maa.json`，3 班 12/6/6，闲置入宿开，10 人 × 4 宿舍满员）：

| 周期数 | 记忆化之前 | 现在（2026-09） |
|---|---|---|
| 1 | 0.41 s | **0.12 s** |
| 3 | 1.51 s | **0.44 s** |
| 7 | 3.41 s | **1.14 s** |

P4-3（挂件判据探针缩小）之后同机交替 A/B：7 周期 **1893 → 1552 ms（1.22×）**；
P7（一批人共享变量快照）之后同机交替 A/B：7 周期 **1525 → 1159 ms（1.32×）**
（3 周期 1.31×、1 周期 1.23×）—— 绝对数随机器负载浮动，看**比例**更靠谱。

**P6a/P6b（增量重算：只算"第一个变了的段"之后的尾巴）**—— 示例排班 7 周期 21 段，全量 ≈1.16 s：

| 编辑 | 增量 | 切点 |
|---|---|---|
| 周期 7→6（只截断） | **7.6 ms** | —— |
| 周期 6→7 | **182 ms** | 第 18 段 |
| 改第 7 周期第 1 班的心情锚点 | **187 ms** | 第 18 段 |
| 改第 7 周期第 3 班的逐次设置 | **72 ms**（省 94%） | 第 20 段 |
| 改某班布局 / 房间等级 / 练度 | 926 ms（**只省 4%**） | 第 2 段 |
| 改初始心情 / 总开关 / `detached` | 全量 | 第 0 段 |

⚠️ 切点由 `Session._segment_signatures()` 的**逐段输入指纹**算出来，所以"改班次布局"这类
"每周期都会重现的段"最早切点永远在第 1 周期 ⇒ 省不了多少 —— 那要靠**引擎本体**（P7 做掉了其中
最肥的一块：变量快照共享）。
口径与坑见 `AGENTS.md` 坑 23 第 ⑤⑥ 条、`documents/07-设计史.md` P9「六」「七」「八」。

三处记忆化 + 一处**世界级共享**（见 `AGENTS.md` 坑 23；动它们就要连回归一起动）。旧版挂件判据探针已随闲置入宿规则重写删除：

1. `rules._active_skill_ids` / `rules._skills_of`：按 `(精英化, 等级, len(skill_ids), id(skill_ids))`
   缓存在**干员实例**上（只依赖技能槽 + 练度）。原来一次 7 周期重算被调 **112 万次**。
   ⚠️ 别再往里加缓存：试过合并成"带红脸态"的缓存，A/B 只有 1.01×（＝白做，见 07-设计史 P9「八」）。
2. `models.BaseLayout._name_index()`：`facility_of` / `get_operator` 的懒建名字索引。
   ⚠️ **设施成员一变必须 `world.invalidate_index()`**（调用点全在 `rules.py`）。
3. （旧版已删除）`rules._all_rates` 的挂件判据速率表不再参与闲置入宿决策。
   （旧版挂件判据说明已废弃。）
4. （旧版已删除）`rules._pendant_probe_names` 与 `_dependent_holders` 不再是闲置入宿性能路径。
   （旧版探针范围与相关回归已废弃。）
5. `rules.net_rates(world, names)`：**一批人共享一份变量快照**（`collect_variables` 是**世界级**的）。
   调用点：`store.schedule.rates_in_world` / `evaluate` / `evaluate_base` /
   `simulator.simulate`。⚠️ 快照与"世界的成员 + 心情"绑定 ⇒ 只在**同一个世界快照、连续算一批人**时共享；
   世界一变必须重收。
   回归 `Test变量快照共享`。

怎么量（照抄即可，改完对比这三个数）：

```python
import time
from data.paths import MAA_SAMPLE
from store.session import Session

for cycles in (1, 3, 7):
    s = Session()
    s.load_paths([MAA_SAMPLE])
    s.set_cycles(cycles)
    best = 9e9
    for _ in range(3):                       # 取 3 次最小值，去掉调度噪声
        t0 = time.perf_counter()
        s.recompute()
        best = min(best, time.perf_counter() - t0)
    print(cycles, "周期", round(best * 1000), "ms")
```

要热点分布就用 `cProfile` + `pstats(..., sort_stats("tottime"))`：顶部应当只有
`mood_ledger` / `consume_ledger` / `_dorm_ledger` / `collect_variables` 这类**真在算**的函数；
如果又冒出 `_active_skill_ids`、`facility_of`、`_is_pendant` 占大头 —— 说明某处缓存被绕过了。

⚠️ **做 A/B 必须"交替多轮"，别信单次对照**（2026-09 踩过）：同进程里"先跑旧、再跑新"，
第二次往往因为**预热 / GC 状态**快 10% 左右 —— 我据此把 `Contribution(slots=True)` 判成 1.12×，
换成"两种配置轮流各跑 4 轮、取最小值与中位数"之后真相是 **0.99~1.01×（＝没用）**，已回退。
同理 `cProfile` 的**调用次数**也会骗人：`_skills_of` 的 112 万次调用看着占 16.6%，
按它去做"合并缓存"实测同样只有 1.01×（profiler 的 per-call 开销被算进去了）。
**判断标准**：先看"交替多轮"的墙钟比值，再用 profile 解释原因，不要反过来。

**编辑不冻界面（P5，2026-09）**：界面上的编辑走 `ui/app.py: recompute_async()` —— 工作线程算、
主线程 `after(30, _poll_recalc)` 收结果并 `Session.adopt()`；导入/测试/程序路径仍用同步的
`Session.recompute()`。四条硬规矩：

1. **连续编辑只落地最后一版**（请求代数 `_recalc_gen`，过期结果丢弃）；测试/面板要等落地用
   `app.wait_recalc()`。
2. **面板还在防抖就先别落地**（`SettingsDialog.has_pending_edit()`）：落地刷新会按轨迹重写格子，
   把用户刚敲的值盖掉（实测"改泡泡 8 后 `apply_batch` 收到空 mood"）。换排班（`load_paths`）
   则把在算的整代作废。
3. **`decimal` 上下文是线程局部的**：引擎入口（`simulate_schedule` / `rules.evaluate` /
   `evaluate_base`）都先调 `config.use_project_decimal_context()`，否则工作线程用
   `ROUND_HALF_EVEN`，末位差 1e-26 会被阈值吸附放大成**事件时刻不同**（回归 `Test线程与精度`）。
4. **GC 只许在主线程跑**：`gc.disable()/enable()` 是**解释器级**的，所以工作线程只调
   `_gc_off_for_worker()` / `_gc_worker_done()`（**只关不恢复**），恢复一律由主线程路径
   `_gc_on_when_idle()` 做。漏了这条就可能让 Tk 对象在非主线程被回收 ⇒
   `Tcl_AsyncDelete: async handler deleted by the wrong thread` **崩进程**
   （回归 `TestGC只在主线程跑`，详见 10-图形界面.md §7.1 第 19 条）。

## 9.6 打包成 exe（PyInstaller，onedir）


**打进去什么**（白名单打法，`scripts/build_exe.py: ADD_DATA` 是唯一来源）：

| 打进 | 不打进 |
|---|---|
| Python 运行时 + tkinter/tcl | `tests/`、`scripts/`、`documents/`、`scenarios/` |
| 本项目的包（`data` / `mood_soc` / `store` / `ui` / `api`） | `.venv/`、`.git/`、`.idea/`、`__pycache__/` |
| `data/operators.txt`（运行时唯一要读的文本，92 KB） | **`resources/` 整目录**（样例 / docx / 报告 / 字典） |

用户口径（2026-09）：**"exe 文件内不保留测试数据"**。连带后果两条，都是**有意的**：

1. 界面冷启动**不再自动载入示例排班**（`ui/app.py` 的 `if SAMPLE.exists()` 恒假）⇒ 空界面；
2. 任何读 `resources/…` 的取用处都必须在 exe 里容错 —— 现在只有那一处冷启动，
   `RES` 也只在文件对话框的 `initialdir` 里用过一次。

**路径怎么找**：`data/paths.py: project_root()` 在冻结时返回 `sys._MEIPASS`（onedir 是
`<dist>/RhodesMoodSOC/_internal`）。⚠️ **不要**改成拿 `__file__` 的上两级去猜：那属于
