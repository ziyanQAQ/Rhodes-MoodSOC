## 2. 已修（2026-10，两个提交）

> 这一族 bug 的**共同特征**：**静默**。没有异常、没有日志、界面看着"成功了"，
> 而世界一点没变 —— 所以只能靠"改完再读一遍世界"的断言抓住它们。
>
> 提交：`1e707ca 修位次读写`（P0-1/2/3）、`5c93547 补增量指纹`（P0-4）。

### 2.1 根因：**读位次的人各自去读 `operators`**

布局的占位有**两种写法**（`mood_soc/models.facility_occupancy`）：

```json
{"operators": ["甲", "乙"]}                  // 紧凑：位次 = 下标（绝大多数设施、老文件）
{"slots": ["甲", null, "丙", null, null]}    // 有位次空洞：空槽写 null（长度 = 到过的最大位次）
```

**`slots` 优先于 `operators`**（两者同时出现时以 `slots` 为准）。而曾经有 6 个地方
只读 `operators`，于是在"留过空洞"的设施上全部**静默失效**；`_write_seats` 又只 pop 掉
`operators`、把过时的 `slots` 留在原地，于是"写进去的新值"被旧值盖掉。

**统一口径**（现已落地）：读位次走 `Session._seat_specs` / `models.facility_occupancy`；
写位次走 `Session._write_seats`（它**无条件把两份写法都摘掉、再写其中一份**）。

### 2.2 四个缺陷的实测证据与修法

| # | 缺陷 | 修前实测（复现脚本） | 修法 | 回归 |
|---|---|---|---|---|
| **P0-1** | `_write_seats` 写紧凑形式时**不清**旧 `slots` ⇒ 改人静默丢弃 | 设施 `{"slots": ["路人甲", null, "路人乙"]}` 上 `set_slots(0, 0, ["路人甲","路人乙","黍"])` → 字典里 `slots` 与 `operators` **同时存在**，世界仍是 `[路人甲, 路人乙]`（黍没进去） | `_write_seats` 先 `pop("slots")` + `pop("operators")` 再写一份 | `tests/test_seat_writes.py::test_set_slots_在带空洞的设施上真的生效` |
| **P0-2a** | `set_training` 只遍历 `operators` ⇒ slots 型设施上**静默无效** | `set_training(elite=1, level=20)` 返回 `changed = 0`、练度仍 E2/30，**无异常无提示** | 改走 `_seat_specs` / `_write_seats`（并保留空洞、不把练度对象拍成纯名字） | `::test_set_training_认_slots_型设施`、`::test_缩容量不丢练度对象` |
| **P0-2b** | `fill_from_pool` 守卫拿"已就位总人数"与"池大小"比大小 ⇒ 该填时不填 | 场内已有 2 人、池里 2 人 ⇒ **一个人都不填**，却仍 `replaced_shift` 一遍 | 守卫改成"池里还有没有没用过的人"；并**先填空洞**再从尾部续放 | `::test_fill_from_pool_按容量而不是池大小`、`::test_fill_from_pool_先填中间空洞` |
| **P0-3** | `set_detached` 摘不掉 slots 型位置 ⇒ **不变式破裂** | `set_detached(['路人甲'])` 后她**既在名单、又在制造站上班**（与第 17 条坑"名单里的人会被从所有班次摘掉"直接矛盾） | `_remove_from_slots` 改走 `_seat_specs` / `_write_seats` | `::test_set_detached_认_slots_型设施` |
| **P0-4** | `_world_digest` **漏字段** ⇒ 增量重算算出旧结果 | 单班 2 小时，**只**把宿舍氛围 1000 → 5000：逐段指纹**完全相同**（引擎认为"没变"），增量给 **9.8**、全量给 **13.0** | 摘要补 `capacity` / `atmosphere` / `slots 位次形状` / `manual.slots` / `manual.names` | `tests/test_equivalence.py::Test增量重算::test_只改宿舍氛围也要被指纹抓到`（+ 手动台账、挪位次两条） |

顺带修掉的同一根因：`facilities_of` 不再给 `slots` 型设施塞一个**空的假 `operators`**
（读的人看到"空房间"的源头之一），并改为返回真正的独立副本。

### 2.3 一条口径**没有**改（故意的）

`_remove_from_slots` 摘人时仍然**把后面的人往前挪**（紧凑化），而
`models.remove_occupant`（`set_seat` 那条路）的口径是"**留空洞、不左移**"。
两者不一致，属于**口径问题而不是崩溃问题**，改动会影响导出形态与闲置入宿锁定区的判定，
所以**这轮保持原样**，登记在 §3.2 的第 2 条等你裁决。

## 6. 已排除（**看着像 bug，其实不是**）

| 现象 | 结论 |
|---|---|
| `ui/app.py:_refresh_layout` 的布局签名里带 `id(world)`，而 docstring 说"用内容签名" | **不是 bug**：`Trajectory.world_at(t)` 返回的是**该段存下来的同一个对象**，`id` 稳定；带上它是为了在**内部换班执行点**上也能重画（内容可能一模一样）。只是措辞与实现不完全一致 |
| `entry_when` 两处默认不同（`session` = `"full"`、`schedule` = `"immediate"`） | 由 `recompute_inputs` **显式传值**弥合，运行期不会用到引擎那份兜底默认 |
| `mood_soc/rules.py` 里 `_active_skill_ids` 把结果缓存在干员实例上（`deepcopy` 会把缓存一起复制） | 缓存键含 `id(skill_ids)`，副本里自然失效 ⇒ **安全**（代价是副本要重建缓存，属性能噪音） |
| `tests/`、`scenarios/`、`_scratch/` 不在 git 里 | **符合约定**（`AGENTS.md` 维护约定 5：测试产物一律不入库） |
| `documents/` 里引用 `resources/心情消耗回复和工休时间.docx` | **故意**的：需求文档不入库，只在本地与历史里 |
