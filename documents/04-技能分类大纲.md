## 1. 六条正交轴

任意一条技能 = 六轴上的一个点；**模板 = 真实数据里出现过的 (B,C,D,E,F) 组合**，给稳定 ID。

| 轴 | 含义 | 取值 |
|---|---|---|
| **A 建模地位** | 要不要算 | `A1` 心情速率 / `A2` 心情事件 / `A3` 心情当条件 / `A4` 非心情 |
| **B 作用域** | 作用到哪个空间 | `B0` 自身设施 / `B1` 同设施 / `B2` 跨设施 / `B3` 宿舍 / `B4` 全局规则 |
| **C 作用对象** | 作用到谁 | `C1` 自身 / `C2` 同设施全体 / `C3` 同设施其他 / `C4a` 宿舍全体 / `C4b` 宿舍单体 / `C5` 条件筛选 / `C6` 全基建 |
| **D 效果** | 改哪个量 | 心情 5 族 / 产出 8 族 / 变量 / 特殊订单 / 设施计数 |
| **E 数值形态** | 参数长什么样 | `E1` 定值 / `E2` ×等级 / `E3` ×设施数 / `E4` ×人数 / `E5` 阈值 / `E6` 池 / `E7` 集 / `E8` 倍率 / `E9` 解锁链 |
| **F 叠加规则** | 多来源怎么合 | `F1` 求和 / `F2` 同种取最高 / `F3` 跨干员取最高 / `F4` 互斥 / `F5` 替换 / `F6` 池 / `F7` 归零优先 |

> **「规则修饰」不单独成族**（并入 **F 轴**）：描述里的「同种效果取最高 / 特殊比较规则 / 归零 / 恒定 / 除以 / 优先生效」只改**怎么合**，不改**改什么**。

### 1.1 一条铁律：模板挂在 clause（子句）上

一个 buff 常含多个子句，子句可属不同族：

| buff | 子句 ① | 子句 ② |
|---|---|---|
| `trade_cost&bd2[000]` 跋山涉水 | 贸易站全体心情消耗 −0.1（`M05`/`A1`） | 每有 10 点人间烟火再 −0.01（`M05`/`A1`，条件槽空） |
| `dorm_rec_all&oneself[011]` 挣脱 | 自身 +0.1（`M10`） | 除自身外全体 +0.1（`M08`，`exclude_self=true`） |
| `control_mp_lonely[000]` 公事公办 | room1 +0.1（`M02c`） | `spread` 扩散白名单（同一子句的参数） |

⇒ `moods_skills.txt` 是 **clause 级**（建模用），`skills_registry.txt` 是 **buff 级**（防漏用）。

## 5. 已拍板的口径与规则（决策记录）

### 5.1 巫恋「低语」= 全体**含自身**

原文「…同时**全体**心情每小时消耗 +0.25」——「全体」＝站内全体（含她自己）。

| 项 | 内容 |
|---|---|
| 数据 | `trade_ord_vodfox_000` 的 `family`：`room_others` → `room` ⇒ `FACILITY_CONSUME`（`M05`，`include_self=true`） |
| 影响 | 自身净消耗 `1 − 0.1 − 0.25(裁缝α) = 0.65` → `0.65 + 0.25(低语) − 0.25 = 0.65`（不变） |
| 后果 | `M06`（不含自身）**保留但无使用者**；将来出现「其他干员」类技能直接用它 |

### 5.2 `M02b` 取最高（实现）

`cc.c.sui2_1`：「在**公事公办**、**孤光共照**、**巴别塔之帜**提供的『其他设施』每小时心情恢复值中**取最高**生效」。

- 口径：**同一干员自己的 clause 先求和，再跨干员取 max**（「取最高」约束技能之间，不约束分句之间）。
- 数据 / 引擎：子句带 `max_group=room2_recover`，`rules._work_recovery` 按 group 取最高。
- 例：玛恩纳 + 重岳 + 维什戴尔同在中枢，制造站目标 = `max(0, 0.05, 0.1) = 0.1`（旧实现求和 0.25 → 高估）。

### 5.3 `M02c` 玛恩纳扩散（实现）

`cc.c.skill`「部分技能」列出 **15 条**白名单（`control_mp_cost_000`~`014`：左膀右臂、S.W.E.E.P.、零食网络、清理协议、替身、必要责任、护卫、小小的领袖、独善其身、笑靥如春、金盏花诗会、捍卫之道、博识生手、点滴关照、总工程师；id 表烧进 `skills_data.SPREAD_SKILL_IDS`，运行时无需上游仓库）。玛恩纳在中枢时，**这 15 条的回复值额外作用到 room2（其他设施）内工作状态的干员**。

- 数据：`公事公办` 带 `spread=cc.c.skill`。
- 引擎：`rules._reaches` / `_spread_active`——扩散提供者**红脸（心情 ≤ 0）时扩散失效**。
- 例：中枢 `[玛恩纳, 陈]` → 制造站目标回复 `0.05`；无玛恩纳则 `0`。

### 5.4 `untranslated` → `partial`（模板确定 + 条件槽空 → 保留效果骨架）

| 字段 | 语义 |
|---|---|
| `partial=true` | 模板已确定，但**某个条件槽是空的**（原 `status=complex`） |
| `partial_mode="apply"` | `value` **本身无条件成立**，缺的只是额外加成/倍率 ⇒ **按骨架生效** |
| `partial_mode="hold"` | `value` **本身以缺失条件为前提** ⇒ 保留模板与骨架，但**仍不生效** |

判定（`scripts/classify_skills.py`）：条件文本**为空**或含「**额外**」⇒ `apply`；其余（每有 / 每个 / 阈值 / 共事）⇒ `hold`。`partial_mode` 只**给新行填初值**，机制实现后**人工回填**（P3 变量、P4a 可数基准、P4b 分支、共事/目标筛选、M15a、P5d 投资）；**当前 250 条 clause 已无 `hold` 实例**（最后 2 条＝投资·α/β，§5.10）。

**只放宽，不收紧**：只在「老逻辑本来就不生效」的子句上放宽，`COND_MARKERS` / `FACTION_COUNT_SKILLS` / `COOP_COND` 命中项不受影响。结果：不生效子句 **37 → 31**，重新生效的 6 条都是 `dorm_rec_single*` 的 `#1` 基础分句（`dorm_rec_single&tag_000#1`、`dorm_rec_single_P_000#1`、`dorm_rec_single_P_001#1`、`dorm_rec_single_P_002#1`、`dorm_rec_single_power_000#1`、`dorm_rec_single_power_001#1`）：`0.55` 是**基础恢复**，`+0.45` 才是条件额外（见 §5.6）。

**曾经的反例**：孤光共照 `#2`「每有 20 点人间烟火 +0.05」的 `value` **本身**以计数器为条件 ⇒ 当年 `hold`；**P3 变量账本做出来后**转 `apply`（`var=人间烟火;var_per=20`）。

### 5.6 `M09` 定向加成「如果目标是 X，则恢复效果额外 +0.45」（实现）

上游 `buffs` 里 **6 条** `dorm_rec_single*` 原文：「…每小时恢复 **+0.55**（同种效果取最高），**如果目标是 X，则恢复效果额外 +0.45**」。本地 CSV 当初把它们塞成**一行**（+0.45 写进 `condition` 列）⇒ 基础 0.55 生效、定向加成整个丢失。**处理**：按原文**手工拆出 `clause#2`**（本项目第一次手工补分句），与 `#1` 同 `skill_id`，value = 450 千分位，条件挂在 `generate_skills_data.CLAUSE_COND`：

| `skill_id` | 技能（持有者） | 目标 | 条件函数 |
|---|---|---|---|
| `dorm_rec_single_P_000` | 沏茶（黑） | 锡兰 | `_cond_target_is("锡兰")` |
| `dorm_rec_single_P_001` | 烤肉大师（特米米） | 嘉维尔 | `_cond_target_is("嘉维尔")` |
| `dorm_rec_single_P_002` | 毒剂师之友（深靛） | 蓝毒 | `_cond_target_is("蓝毒")` |
| `dorm_rec_single_power_000` | 降生于冰寒（寒檀） | 萨米 | `_cond_target_in_faction("萨米")` |
| `dorm_rec_single_power_001` | 圣城趣事通（新约能天使） | 拉特兰 | `_cond_target_in_faction("拉特兰")` |
| `dorm_rec_single&tag_000` | 狩猎好帮手（罗德岛隐秘队） | `cc.tag.mh` **和** `cc.tag.mh2` | `_cond_target_in_faction("怪物猎人小队", "泡影国狩猎小队")` |

1. **条件函数两类**：具体干员用 `_cond_target_is(…)`（可多个）；阵营/标签用 `_cond_target_in_faction(…)`（**可变参数**，表达「怪物猎人小队**和**泡影国狩猎小队」这种并集，即 `cc.tag` 两个标签）。
2. **「同种取最高」的单位是技能，不是分句**（同 `03-特殊机制.md` 第 18 条）：`_single_recovery` 旧按分句取 `max` 会吃掉 +0.45；现记进 `MoodLedger`，用 `MoodLedger.same_kind_winner(bucket, group)` 取**获胜技能实例**（同 `skill_id` 求和 → 1.00，再与「使徒」0.50 取最高）；`same_kind_winner` 与 `total()` 的 `SAME_KIND_MAX` 分支**同源**。
3. **点名守卫**：`check_faction_refs()` 扫 `CLAUSE_COND` 字面量——`_cond_target_in_faction("…")` 须真实阵营、`_cond_target_is("…")` 须真实干员名（名册取 `data/operators.txt` **全量**，不能用 `DEFAULT_OPERATORS`：锡兰/嘉维尔/蓝毒只有生产/训练技能）；「萨米X」「蓝毒X」都会被拦。

> ⚠️ `_single_recovery` 的**目标锁定**是"心情最低、未满、且不持有单体回复技能的干员"（全局一名受益者，见 `03-特殊机制.md` 建模假设 5）；「毒剂师之友」上游虽**没有**「除自身以外」，本模型仍把深靛排除在候选之外。

### 5.7 `M17` 元修正：一名干员强化**另一名干员**的效果（实现）

原文（`buffs["dorm_rec_toone[000]"]`）：「进驻宿舍时，**推进之王**对该宿舍中**格拉斯哥帮**干员恢复效果额外 **+0.3**」。

| 要素 | 取值 |
|---|---|
| 数据行 | `dorm_rec_toone_000`，`family=dorm_meta` → `SkillKind.DORM_META`，`template_id=M17` |
| 被强化者 | `params` 的 `boost_provider=推进之王` |
| 强化的那一组 | `params` 的 `boost_group=dorm_group` |
| 目标筛选 | `CLAUSE_COND`：`_cond_target_in_faction("格拉斯哥帮")` |

**实现铁律**：增量必须记成**同组、同 `skill_id`、同 owner** 的额外贡献，让 `SAME_KIND_MAX` 并入被强化技能的小计（0.2 → 0.5）**再**去和其他技能比；记成独立技能会被"同种取最高"当成竞争者（`max(0.2, 0.3) = 0.3`，反而更小）。与 §5.2、§5.6 是**同一条轴 F 铁律**的第三次应用。
⚠️ 范围仅限**宿舍**（`_dorm_ledger` 内的元修正段）；被强化者必须与摩根**同设施**且未红脸。

### 5.8 `M15a` 进驻事件：**进驻那一刻**的状态跳变（实现）

原文（`dorm_exchangeAp[000]`）：「进驻宿舍时，**如果自身为满心情**，则与当前宿舍**前一位进驻**的干员互换心情」。**关键判断**：不是速率——塞进 `consume_ledger`/`recovery_ledger`（"每小时"）或时间积分（只在 t=0 一次）都错，它是**布局初始化**语义：

| 要素 | 取值 / 做法 |
|---|---|
| 数据 | `template_id=M15a`，`partial_mode=apply`（原为 `hold`） |
| 触发者 | **本班任一设施的在岗干员 ∨ 本班未排班 ∨ 显式「不在基建」名单**（满足其一即"存在"；判据＝「实时心情表里有、这一班的世界里没有」，**不是** `world.detached`，见 `03-特殊机制.md` 第 29 条） |
| 触发条件 | `CLAUSE_COND` → `_cond_self_full_mood`（自身心情 == 24）；⚠️ `when` 三档**都要过**这道门 |
| 调度 | `rules._template_skills(op, "M15a")`（按模板而非 kind，同 `03-特殊机制.md` 第 25 条 的 `M07b`） |
| 结算入口 | **`rules.apply_entry_events(world, …, detached_moods=…)`**，CLI `--entry-events`；**就地**改心情 |
| 流水账 | `Bucket.EVENT`（不参与 rate），`--entry-events` 时打印到 stderr |
| 「前一位进驻」 | `Facility.operators[idx-1]`——**该列表本来就是进驻顺序**；她不在这一班任何设施里时没有「前一位」（记 `entry_swap_skipped`） |

### 5.11 全量核对（**机器保证"每条技能都对、每位干员都生效"**）

| 层 | 对象 | 核对方式 | 现状 |
|---|---|---|---|

### 5.12 夕「不以物喜」改判回复侧（L3 描述对照抓出来的）

全量核对（§5.11）第一次跑就抓到：上游 `buffs["control_mp_cost&bd1[000]"]` 原文是「…控制中枢内所有干员的**心情每小时恢复** +0.05」，而本仓库当初按 `M05`「同设施全体**消耗** -0.05」（`facility_consume`）建模。

| 项 | 旧（错） | 新（按上游） |
|---|---|---|
| kind / 模板 | `facility_consume` / `M05` | **`cc_recover` / `M03`**（中枢内全体回复） |
| value | `-0.05`（减耗） | **`+0.05`**（回复） |
| 数据 | `data/moods_skills.txt`：`drain,room,M05,include_self=true` | `recover,control_room,M03,target=cc_all` |

- **净效果看似一样**：对正常消耗的干员，少耗 0.05 ≡ 多回 0.05。
- **哪里不一样**：消耗侧末尾有「**钳位 ≥0**」——消耗已被减到 0 时旧口径给 0、新口径仍给 +0.05；模板归属错了还会让"同种取最高"的分组不对。
- **怎么发现的 / 回归**：`verify_skills.py` 的 L3 抽描述里的数字并看邻近的词是「消耗」还是「恢复」；回归 `tests/test_skill_coverage.py::test_不以物喜按上游原文走回复侧`。

## 6. 导入新干员技能的流程

```
新干员（或旧干员新技能）
  1. 更新 data/operators.txt（干员↔buff 映射 + 解锁）
  2. 跑 scripts/classify_skills.py --agd <仓库>：buff 落进 data/skills_registry.txt（755 → 756…）；
     未命中模板 → template_id = "??" → 校验失败并打印清单
  3. 看校验输出：命中 M01~M17 → 在 moods_skills.txt 加 clause 行（template_id + params）；
     落 X 族 → 无需动作；未命中 → 人工判定（新模板？旧参数？）后补进 skill_templates.py
  4. 跑 scripts/generate_skills_data.py → 重写 data/skills_data.py
  5. 跑 .venv/Scripts/python.exe -m unittest discover -s tests
```

**机器保证**：`classify_skills.py --check` 断言 ①`moods_skills.txt` 每行的 `template_id` 都在注册表里；②`skills_registry.txt` 行数 == 上游 buff 总数；③无 `tier=??` 行。任一不满足即退出码 1。
**再加两道路闸**（§5.11）：`verify_skills.py --check` 断言 ④上游 755 条 buff 与 clause **双向对上**（`modeled` 标记不能骗人）；⑤每条 clause 在**满足它条件的场景**里按模板口径生效。只改数据没跑核对 ⇒ `tests/test_skill_coverage.py` 会红。
