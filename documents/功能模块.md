# 功能模块规范

## 1. 模块总表

| 模块 | 输入 | 输出 | 写权限 |
|---|---|---|---|
| 时间轴 | 班次、周期、时长 | 执行点和区间 | 时间轴内部 |
| 布局 | 设施、位次、台账 | 基线/模拟布局快照 | 布局命令 |
| 名册 | 干员、技能、练度 | 稳定名册和技能索引 | 名册装配 |
| 心情 | 初始心情、速率、事件 | 实时状态和轨迹 | 心情积分器 |
| 自动化 | 设置、布局副本、实时心情 | 换心情/入宿事件 | 自动化策略 |
| 编排 | 各模块快照和设置 | `SimulationResult` | 唯一跨模块写入口 |
| 查询 | 不可变结果、查询条件 | 曲线、快照、明细、统计 | 无 |

## 1.1 核心对象关系

```text
Catalog(Operator, Skill, FacilityType)
  └─ Roster(OperatorId, Elite, Level)
Schedule(Shift[])
  └─ Shift(FacilityLayout, ManualLedger, Duration)
SimulationInput(Schedule, Roster, InitialMoods, Settings, Versions)
  → SimulationRun(Trajectory, Segment[], Event[], Warning[])
  → QueryProjection(Curve | Snapshot | Detail | Statistics)
```

`Schedule` 是用户编辑和保存的基线。`SimulationRun` 持有其不可变输入摘要及计算副本产生的轨迹；查询投影从已发布结果生成。对象引用用稳定 ID，禁止跨层共享可变房间或干员对象。

## 2. 用例

应用层提供 `validateInput`、`simulate`、`curve`、`snapshot`、`detail`、`events`、`entryCandidates`、`idleCandidates`、`settingsSchema` 和 `capabilities`。每个用例都有稳定输入输出 DTO，UI、Worker 和程序 API 不得绕过应用层访问领域对象。

用例端口约定：`simulate(input) → SimulationReceipt`；查询用例均接收 `simulationId + revision` 和查询参数；`validateInput` 返回字段路径、稳定错误码和警告；布局编辑用例接收 `scheduleRevision` 与操作命令，成功时返回新草稿版本，冲突时不覆盖较新草稿。

## 2.1 状态所有权

| 状态 | 所有者 | 可变阶段 | 发布后 |
|---|---|---|---|
| 静态目录 | 名册/数据目录 | 目录构建或版本升级 | 只读 |
| 排班草稿与手动台账 | 布局模块 | 用户编辑命令 | 作为模拟输入快照 |
| 实时心情与自动布局 | 单次模拟编排 | 仅计算期间 | 封存为不可变结果 |
| 播放位置、选中干员、图表缩放 | Web UI | 始终由 UI 管理 | 不进入模拟输入 |
| 换心情/入宿设置 | 应用输入 DTO；宿主可持久化 | 用户编辑草稿 | 版本化输入的一部分 |

## 3. 执行顺序

每个班初和内部换班点依次执行：重建原始布局、继承实时心情、换心情、闲置入宿、应用同刻心情指定、重算速率、积分到下一节点。手动布局属于基线；自动结果属于副本。具体候选和锁定规则以 `入宿逻辑.md` 为真源。

## 4. Web UI 模块

- 排班编辑：班次、设施、位次、手动入宿和清空解锁。
- 模拟设置：周期、初始心情、换心情、闲置入宿、黑名单和锁定位置。
- 心情回放：时间轴、播放、暂停、当前布局和全员心情。
- 干员详情：曲线、红脸区间、班次统计、速率账本和事件。

UI 可保存设置草稿，但不保存核心结果；本地持久化由宿主适配器负责。连续编辑使用防抖和 `revision`，旧结果不得覆盖新结果。

## 5. 不变式

1. 领域层不依赖 UI、Worker、HTTP 或 JSON。
2. 查询模块只读，自动化不回写排班基线。
3. 手动锁保护位次和人员；自动行为遇锁不得破坏。
4. 同一规范化输入与版本产生确定性结果。
5. 所有跨模块写入由编排器协调。
6. 所有稳定关联使用 ID，不使用显示名或运行时对象。

## 6. 验收矩阵

领域测试覆盖心情积分、技能账本、时间边界、同刻跳变、换心情、闲置入宿、手动台账和 28 条入宿不变式。适配器测试覆盖 Worker 消息、协议校验、RIIC-Web 输入转换和过期响应丢弃。UI 测试覆盖设置编辑、回放和错误展示。

## 7. 状态分级

“已定规则”表示文档已确认；“设计契约”表示接口已定义但无源码；“待实现”表示计划功能；“待核实”表示数据来源或游戏事实尚未确认。文档不得把规划写成已实现。
