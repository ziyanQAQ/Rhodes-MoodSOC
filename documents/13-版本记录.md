## 未发布（2026-10）：闲置入宿「三层解耦」

**一句话**：把「手动入宿」与「自动入宿」解耦成三层，明确优先级
**手动编辑 > 自动入宿 > 导入布局**；手动入宿从"设置面板里的第二套写法"改成
**布局编辑本身**（写班次快照 + 手动台账），自动入宿重写成可判定、可终止的两相算法。

| 项 | 旧（v1.1 及以前） | 现 |
|---|---|---|
| 手动入宿 | 闲置入宿面板的逐次表：`宿舍NN` / `宿舍NN·第M位` / 点名某人（引擎按配置执行） | **看板 / 「干员与心情」**写**班次布局 + 手动台账**（`facilities[].slots` / `manual`）；面板那一列已删 |
| 手动标记 | 无（导入与手改在数据里同形） | `models.ManualLedger {slots, names}` 挂在设施上；**导入不打标**；钉住的位次/人自动入宿不碰 |
| 换人目标 | 竖向**反序**扫描，取首个**严格大于**候选的住户 | 取"**≥ 候选且心情最大**"的住户（并列取竖向正序最靠前）—— 这样才达到"宿舍装进全体里心情最低的那批"的定点 |
| 被换出者 | 追加队尾，可能在同一执行点被再处理 | **不在本执行点再入队**（下一个执行点重新评估）—— 实测"插回队列"永远改变不了结果，只会打转 |
| 空位 | "连续排列"：唯一可入住位＝现有人数 + 1 | **竖向正序第一个空位**（含中间空洞）；清空某位**不左移**（`models.set_seat`） |
| 面板逐次表 | 每行「位置 / 换谁」下拉 | 每行只有「参与」+ 一列**只读**的"引擎安排了什么"（`Trajectory.idle_note_at`） |
| API | `set_idle_to_dorm` 的 `per_operator[].target` 三类 | `per_operator` **只剩"参不参与"**；旧写法读得进来但被忽略，回一条 `notes` |
| 锁定位置 | 键是 `id(facility)` ⇒ **静默失效**（排班层先在 pristine 上算、再在每段深拷贝上跑） | 键是 `rules._seat_key(world, fac)`＝`(类型, 实例名)` 或 `(类型, 世界下标)` |

### 2. 长班内部换班执行点（v1.0 没有）
`store/schedule.execution_offsets` / `execution_points`：每个真实班次的**班初** ＋ 班内每个
**严格小于班末**的 12h 整数倍 —— `12h→[0]`、`18h→[0,12]`、`24h→[0,12]`、`25h→[0,12,24]`。
每个执行点都**从该班原始布局重建位置**、重跑进驻事件与闲置入宿、并记一条可见标记
（`第 1 班 · 12h 内部换班`，**即使没事发生也记**）；内部换班**不增加班次数、不改班次编号**，
同周期同班次的所有执行点**共用一份逐人设置**（`(周期, 班次)` 键）。界面上按执行点分组显示。

### 3. 发电站「有效间数」（新增"仅影响设施数量"类技能）

`data/facility_count.py` + `mood_soc/facility_count.py`：`有效间数 = 实际间数 + Σ(条件成立)`：

- 森蚺「我寻思能行」：**控制中枢** ∧ **Lancet-2 进驻在发电站** ⇒ 发电站 **+2**（**不看心情**）；
- 承曦格雷伊「晨曦」：**发电站** ∧ 其他发电站内没有**有效的**作业平台 ⇒ 发电站 **+1**（红脸平台**不阻断**）。

唯一消费方是流明「柔和微光」的 `+0.05/间` ⇒ 典型算例 **4.25 → 4.35**。
两条技能的**条件不对称**是用户拍板的口径，别互相"对齐"。只改"数出来几间"，**布局/容量/进驻位一律不动**。

### 4. 看板跟着换班执行点换

内部换班点**不改 `shift_index`**，所以"要不要重画看板"不能只判"班次号变了" ——
判据改成"**这一刻那份引擎世界还是不是上一次画的那一份**"（`world_at(t)` 每个执行点各给一份深拷贝）。
用户报过的"内部换班时 UI 没有显示对应布局"就此修掉，回归逐点断言"看板槽位 == 引擎槽位"。

### 5. 线程与关窗口健壮性（**修"崩进程"**）

- **GC 只许在主线程跑**：工作线程入口 `_gc_off_for_worker()`、出口 `_gc_worker_done()`（**只减计数**），
  恢复一律由主线程 `_gc_on_when_idle()`；`destroy()` 把在算的线程**有界 join** 干净。
  原先"窗口已销毁、工作线程还在跑"时，线程里的一次 GC 会在**非主线程**回收 Tk 对象 ⇒
  `Tcl_AsyncDelete: async handler deleted by the wrong thread` **直接 abort 进程**（实测合并跑 3 次崩 2 次）。
- `destroy()` 还要撤掉挂着的 `after_idle`，并**上闩**（`RosterStrip._closing`）——
  `Tk.destroy()` 逐个销毁子控件时 Tk **仍会派发 `<Configure>`**，撤一次不够。
- **换排班不再卡住**：`load_paths` 摘掉旧工作线程引用，修掉"界面卡在「计算中…」、曲线还是上一份排班"。

### 6. 界面「闲置入宿」面板重做

① 总开关（**每个换班执行点结算**）＋ ② **锁定位置数** ＋ **黑名单**（下拉加入/移除）＋
③ **按时间排的逐次表**：**一个换班执行点一组**（长班的内部换班点各一组，标题带 `（12h 内部换班）`），
**行序＝引擎的处理顺序**，每行的「位置 / 换谁」按 **轮到她的那一刻**的宿舍态给选项

### 10. 发布阻断修复：设置窗口的 Shift+Tab 绑定（构建期发现）

`ui/settings.py` 里 `self.bind("<ISO_Left_Tab>", …)`：`ISO_Left_Tab` 是 X11 的 keysym 名，
**Windows 的 Tk ≤ 8.6.12 没有它** ⇒ 抛 `TclError`，而这行在设置窗口的 `__init__` 里
⇒ **整个「设置…」打不开**（本次全量测试里 21 个 GUI 用例同时红，就是这么发现的）。
v1.0 的 exe 用 Python 3.14（Tk 8.6.13+）构建，那边认得这个名字，所以一直没暴露。
修法：按 `<Shift-Tab>` → `<Shift-Key-Tab>` → `<ISO_Left_Tab>` **逐个 try、绑上第一个就 break**
（只绑一个：两个都绑在 X11 上可能触发两次）。

> ⚠️ **性能类优化不算本版的新增**：增量重算（P6）与变量快照共享（P7）在 v1.0 就已上线
> （示例排班 7 周期 1.14s 就是 v1.0 的数）。本版顺带的性能收益来自"闲置入宿不再做挂件/阵营探针"
> —— 那套判据在 v1.0 占一次重算约 13.6%，随重写一起归零。
