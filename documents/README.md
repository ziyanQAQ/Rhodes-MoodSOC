# documents —— 项目文档

本目录存放**全部文档**。分工原则：

| 目录 | 放什么 | 例子 |
|---|---|---|
| `data/` | **数据（要 import 的表）** | 技能库/台账/阵营表/干员名册（`.txt`）+ 生成物（`skills_data.py` 等）+ `paths.py` |
| `resources/` | **数据（要读文件的）** | 样例 JSON、数据字典说明、核对报告（需求文档 `.docx` 本地保留、**不入库**） |
| `mood_soc/` | **纯计算** | 心情电池 / 规则引擎 / 流水账 / 变量账本 |
| `store/` | **数据管理层** | 排班与整周期轨迹、4 种输入解析、结果序列化、**会话状态** |
| `api/` | **程序接口** | JSON 进 / JSON 出（常驻 NDJSON + 一次性 CLI），供 Rust 调用 |
| `ui/` | **图形界面** | tkinter 视图（状态在 `store.Session` 上） |
| `scripts/` `tests/` `main.py` | **代码**（工具与测试） | 纯标准库 Python；`tests/` **不入库** |
| `documents/` | **文档**（本目录） | 你现在读的这些 `.md` |
| `scenarios/` | **本地目录、不入库** | 测试用场景 JSON（`maa_to_scenario.py` 的默认输出处） |
| 根目录 | 入口 | `AGENTS.md`（AI 入口）/ `README.md`（人类入口） |

> 根目录的 `AGENTS.md` 是**精简入口**——DSH 只从项目根沿 cwd 链自动加载它，
> 所以它必须留在根目录、且保持精简（有 64KB 指令预算）。细节都在本目录。

`resources/` 下的 3 份 `.md`（**不是 `documents/`，因为是"读文件的数据"而非文档门类**）：
`输出JSON结构说明.md`（v3 输出契约的数据字典）· `plan_compute_example_v4_annotated.md`（v4 蓝图样例注解）·
`skill_verify_report.md`（**生成物**，由 `scripts/verify_skills.py --report` 重写）。

## 阅读顺序

**第一次接触本项目**：`../README.md`（人类版全貌）→ `01-架构.md` → `02-数值规则.md`。

**要给某个干员加技能 / 改数值**：`05-数据来源.md`（先查上游）→ `04-技能分类大纲.md`（认模板）
→ `02-数值规则.md` §5（填字段）→ `06-设计史.md`（自查清单 + 测试）。

**要用/改图形界面**：`07-图形界面.md`（`ui/`：多班排班 + 时间滑动 + 对点曲线 + 按时刻指定心情）。

**要让别的程序（Rust）调用**：`08-程序接口.md` §1~§9（`api/`：NDJSON 常驻服务 + 一次性 CLI + 接入样例）
→ 同文件 §10~§18（**v3 侧照抄即可**：调用序列 / 配置字段 / 默认口径 / 踩坑清单）。

**要改引擎逻辑**：`01-架构.md` → `03-特殊机制.md`（**必读**，35 条里有踩过的坑）
→ `06-设计史.md`（为什么是现在这样）。

**要动架构 / 拆模块 / 大改界面归属**：**`09-架构总览.md`**（现状测绘 + 逐条病灶，带 `file:line`）
→ 再回 `01-架构.md`（设计意图）与 `06-设计史.md`（历史决策）。

**动手改代码之前**：`10-现状与校准记录.md` §2（已修，别重复修）→ §3（**未修清单**，扫一遍有没有你要碰的地方）。

**只想"一眼看懂全流程"**：`09-架构总览.md` 末尾的**四张图**（分层大图 / 端到端数据流 / 重算时序 / 界面写路径）。

## §编号约定（重要）

原 `AGENTS.md` 的章节号被当作**稳定 ID** 保留下来，全仓库（含代码注释）里的
`§4.16` / `§8.5` / `§11` 之类引用**依然有效**，按下表换算：

| 引用形如 | 指的是 |
|---|---|
| `§0` `§1` `§6` `§9` | `01-架构.md` 内对应章节 |
| `§2` `§3` `§5` `§5.N` | `02-数值规则.md` 内对应章节（§5 = 技能系统） |
| `§4.N` | `03-特殊机制.md` 的**第 N 条**（1~35） |
| `§7` `§10` | `06-设计史.md` 末尾「附 · 开发指南」内对应章节 |
| `§8.N` | `03-特殊机制.md` 的**建模假设第 N 条**（1~12） |
| `§11` | `05-数据来源.md` |
| `§5.N`（在 `04-技能分类大纲.md` 内） | 该文档**自己**的 §5「已拍板的口径与规则」 |

⚠️ 同一个 `§5.x` 在 `02-数值规则.md` 与 `04-技能分类大纲.md` 里含义不同——
**看它出现在哪个文件里**。

以上是**第一套**编号（原 `AGENTS.md` 的稳定 ID）。仓库里实际还有**三套**，判据都是"看它出现在哪个文件里"：

- **第二套：`09-架构总览.md` 自己的 §1~§14**（§9 模块划分 / §10 状态归属 / §11 接口落点 /
  §12 判据 / §13 实施三步 / §14 与旧方案差别）。`scripts/verify_modules.py` 与
  `tests/test_modules.py` 用的是这一套。
  ⚠️ 它的 `§9` / `§10` 与第一套**撞号**（第一套的 `§9` = `01-架构.md` 的公共 API、
  `§10` = `06-设计史.md` 附开发指南的自查清单）—— **`09-架构总览.md` 文件里的 `§9.x` 一律指它自己**。
- **第三套：`08-程序接口.md` 末尾 §10~§18**（2026-10 并入的 v3 接入部分，原 §1~§9 顺延）。
  与 §1~§9 **不撞号**，所以文件里 §10 以上一律指 v3 接入。
- **第四套：外部文档《闲置入宿完整逻辑》的 §2~§17**（**不在本仓库**，是用户给的需求文档）。

## 维护约定

1. **每次改动（代码 / 数据 / 文档 / 结构 / 数值规则）后，同步更新相关文档**
   （至少 `../README.md` 与受影响的 `documents/*.md`），别让文档和代码分叉。
2. **每次改动立即 `git commit`**，提交信息 1–15 个字（如「修复替换链」「补变量账本」），
   不写多段说明、不加 `feat:`/`fix:` 前缀。一次提交一件事。
3. **根 `AGENTS.md` 保持精简**（有 65536 字节指令预算，超了会被截断、尾部读不到）。
   新增内容写进本目录对应门类的文档，`AGENTS.md` 里只留一行指针。
4. **文档按门类分文件，不要堆成一个大文件**；一个门类一件事，文件名即主题。
5. ⚠️ **`§编号` / `第 N 条` / `坑 N` / 模块名 是跨文件的稳定标识符**（代码注释、`AGENTS.md`、
   自检脚本都在引用）。**再合并文件时不许重编号**：只搬结构、并把引用里的文件名改掉；
   目标文件里如果出现同号，要么换存活方（让号高的层级留下），要么给并进来的部分顺延编号。
6. **合并/改名之后必须自查三件套**（**已入库成常驻检查**：`python scripts/verify_docs.py`，它覆盖 ②③
   外加索引与预算）：
   ① **标识符守恒**（`§编号` / `第 N 条` / `坑 N` / 文件路径 / 反引号术语，做**集合差** ——
   同一术语只要还留一处就不算丢；⚠️ 这条需要一份**合并前的快照**做基线，所以仍是一次性工具，
   用 `_scratch/check_doc_ids.py --snapshot` 在动手前存一份、结束后比对）；
   ② **重复 `§` 与 H1 数**；③ **悬空引用**（每条 `documents/xx.md` 都要落到真实文件上）。
   还要跑 `scripts/verify_modules.py`（它**真的会读** `documents/09-架构总览.md` §9 做一致性检查）。
   ⚠️ **两条教训**：㈠ "指到**存在但错误**的文件"（例：溯源行被改成自指）这种错误
   **悬空引用扫描抓不到**；㈡ 重复 `§` 也要专门检查才会发现 —— 三件缺一件就会漏
   （见 `10-现状与校准记录.md` 的「文档整合（2026-10）」那批）。
   ⚠️ **故意列出已被并入的文件名**（如 `10-现状与校准记录.md` 的「合并映射」表）要夹在

   **不要靠"表格里就放过"这种猜测**：误放过一次悬空引用，这个检查就白建了。
