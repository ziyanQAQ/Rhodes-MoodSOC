# documents —— 项目文档

本目录存放**全部文档**。分工原则：

| 目录 | 放什么 | 例子 |
|---|---|---|
| `mood_soc/` `scripts/` `tests/` `main.py` | **代码** | 纯标准库 Python |
| `resources/` | **数据** | `.docx` 需求文档、`.txt` 技能/阵营/台账表、`.json` 样例 |
| `documents/` | **文档**（本目录） | 你现在读的这些 `.md` |
| `scenarios/` | 示例场景 | MAA 排班转换产物 |
| 根目录 | 入口 | `AGENTS.md`（AI 入口）/ `README.md`（人类入口） |

> 根目录的 `AGENTS.md` 是**精简入口**——DSH 只从项目根沿 cwd 链自动加载它，
> 所以它必须留在根目录、且保持精简（有 64KB 指令预算）。细节都在本目录。

## 阅读顺序

**第一次接触本项目**：`../README.md`（人类版全貌）→ `01-架构.md` → `02-数值规则.md`。

**要给某个干员加技能 / 改数值**：`06-数据来源.md`（先查上游）→ `05-技能分类大纲.md`（认模板）
→ `03-技能系统.md`（填字段）→ `09-开发指南.md`（自查清单 + 测试）。

**要用/改图形界面**：`10-图形界面.md`（`ui/`：多班排班 + 时间滑动 + 对点曲线）。

**要改引擎逻辑**：`01-架构.md` → `04-特殊机制.md`（**必读**，31 条里有踩过的坑）
→ `07-设计史.md`（为什么是现在这样）。

## §编号约定（重要）

原 `AGENTS.md` 的章节号被当作**稳定 ID** 保留下来，全仓库（含代码注释）里的
`§4.16` / `§8.5` / `§11` 之类引用**依然有效**，按下表换算：

| 引用形如 | 指的是 |
|---|---|
| `§0` `§1` `§6` `§9` | `01-架构.md` 内对应章节 |
| `§2` `§3` | `02-数值规则.md` 内对应章节 |
| `§4.N` | `04-特殊机制.md` 的**第 N 条**（1~32） |
| `§5` `§5.N` | `03-技能系统.md` 内对应章节 |
| `§7` `§10` | `09-开发指南.md` 内对应章节 |
| `§8.N` | `04-特殊机制.md` 的**建模假设第 N 条**（1~9） |
| `§11` | `06-数据来源.md` |
| `§5.N`（在 `05-技能分类大纲.md` 内） | 该文档**自己**的 §5「已拍板的口径与规则」 |

⚠️ 同一个 `§5.x` 在 `03-技能系统.md` 与 `05-技能分类大纲.md` 里含义不同——
**看它出现在哪个文件里**。

## 维护约定

1. **每次改动（代码 / 数据 / 文档 / 结构 / 数值规则）后，同步更新相关文档**
   （至少 `../README.md` 与受影响的 `documents/*.md`），别让文档和代码分叉。
2. **每次改动立即 `git commit`**，提交信息 1–15 个字（如「修复替换链」「补变量账本」），
   不写多段说明、不加 `feat:`/`fix:` 前缀。一次提交一件事。
3. **根 `AGENTS.md` 保持精简**（有 65536 字节指令预算，超了会被截断、尾部读不到）。
   新增内容写进本目录对应门类的文档，`AGENTS.md` 里只留一行指针。
4. **文档按门类分文件，不要堆成一个大文件**；一个门类一件事，文件名即主题。
