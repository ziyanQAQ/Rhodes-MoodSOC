# 设施信息规范

## 1. 设施模型

设施分为设施类型和设施实例。类型定义规则、等级上限和默认容量；实例拥有稳定 `facilityId`、类型、名称、等级、启用状态和位次。名称只用于展示，业务关联使用稳定 ID。

## 2. 字段

| 字段 | 含义 |
|---|---|
| `facilityId` | 设施实例稳定 ID |
| `facilityType` | 控制中枢、贸易站、制造站、发电站、宿舍等类型 |
| `level` | 当前等级，不超过类型上限 |
| `capacity` | 当前等级可用位次或房间容量 |
| `slots` | 按位次保存的干员 ID 或空洞 |
| `moodRate` | 基础消耗/回复参数 |
| `enabled` | 是否参与布局和排序 |
| `displayName` | 本地化展示名 |

## 3. 宿舍位次

宿舍采用留洞、不左移模型。位次是 `slotIndex`，从零开始；空位仍保留位置身份。竖向正序用于锁定位置，竖向反序用于填空和并列裁决。停用宿舍不参与排序，也不占用锁定位置数。

未命名实例在运行时以“类型#序号”补充内部稳定名，不写回导入数据。锁定键由设施类型和稳定实例名组成，不能使用运行时对象身份。

## 4. 心情职责

设施提供基础消耗、宿舍回复、技能作用范围和计数基准。具体技能效果由技能目录和领域策略计算；加工站、训练室、活动室等特殊挂件或非入住语义必须在设施能力中显式声明，不能由 UI 猜测。

## 5. 布局写入

导入布局只建立基线，不自动打手动锁。手动放置会写入班次布局和手动台账；清空位次解除对应锁；自动换心情和闲置入宿只修改模拟副本。任何布局写入口必须维护“不在基建名单、占位和锁定”不变式。

## 6. 扩展与校验

新增设施类型需要提供等级表、容量规则、基础心情参数、可容纳角色和技能作用域，并补充导入、快照、曲线和规则回归。等级、容量、位次和名称必须在规范化阶段校验。
