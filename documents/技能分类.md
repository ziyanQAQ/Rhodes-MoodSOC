# 技能分类规范

## 1. 目标

技能分类将“读取描述并改引擎代码”改为“识别模板、填参数、生成目录”。分类是数据治理与扩展机制，不是 UI 标签。

## 2. 六条正交轴

| 轴 | 内容 |
|---|---|
| A 建模地位 | 心情速率、心情事件、心情条件、非心情 |
| B 作用域 | 自身、同房间、指定设施、全局或跨设施 |
| C 方向 | 消耗、回复、事件、修正、计数 |
| D 目标 | 持有者、室友、设施内全体、指定干员或全局 |
| E 条件 | 阵营、练度、设施、心情、变量和组合条件 |
| F 组合 | 叠加、取最高、替换、扩散、元修正或互斥 |

模板挂在最小可计算的 `clause` 上；一个技能可包含多个子句。跨技能比较前先按 `skillId` 聚合其子句，不能把子句误当成独立技能。

## 3. 模板与注册

每条技能目录记录 `skillId`、`operatorId`、`clauseId`、`templateId`、参数、设施集合、条件、效果方向、目标和来源。模板注册表负责解释参数，技能注册表保证上游技能不遗漏。新增模板必须说明适用范围、叠加规则、边界条件和迁移兼容性。

## 4. 计算规则

技能子句的条件求值、组合语义、账本格式、事件与持续速率的边界由 [`心情计算与技能结算.md`](心情计算与技能结算.md) 统一定义。本文只保留分类轴和目录字段；新增模板必须同时补充该真源要求的来源、边界和黑盒测试。

## 5. 数据流程

```text
上游数据 → 原始记录 → 分类器 → 标准化技能目录 → 运行时注册表 → 领域账本
```

生成物不得手工修改。校验至少覆盖模板自洽、技能全量覆盖、条件求值、真实干员关联和参考轨迹等价。

## 6. 扩展原则

新增技能优先新增目录记录和模板参数；只有出现新的行为组合时才新增策略。禁止在 `rules` 或 UI 中加入干员名称分支。无法确认的游戏事实标记为待核实，不当作确定规则。
