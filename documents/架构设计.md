# Rhodes_MoodSOC 架构设计

## 1. 文档定位

本项目是一个排班心情模拟核心：读取规范化的基建布局、干员名册、班次与模拟设置，在每个换班执行点执行换心情和闲置入宿规则，输出可供 Web UI 或程序 API 查询的心情轨迹、布局快照、事件和解释数据。

当前处于分层施工阶段，data 目录与文件 CatalogReader 已有最小实现，状态见 [`施工/01-data层施工.md`](施工/01-data层施工.md)。其余架构与业务规则仍是设计契约。文档中的“已定规则”来自 `入宿逻辑.md` 及参考项目行为；“规划中”表示尚未实现的接口或适配器。

## 2. 设计原则

1. 依赖单向向下，禁止领域层依赖 Web、Worker 或具体存储。
2. 领域规则集中在领域层，UI 只负责编辑、展示和交互状态。
3. 每类状态只有一个写入口；跨模块通过命令、查询和不可变快照交互。
4. 新增技能、设施、事件和输出投影优先通过注册表、策略或适配器扩展，不修改稳定流程。
5. 输入在模拟开始时规范化并冻结；自动行为只修改模拟副本，不回写排班基线。
6. 计算数值采用十进制定点语义；跨进程/跨线程 DTO 使用十进制字符串。
7. 参考项目可作为行为基线，但当前项目的源码事实以本仓库实现和测试为准。

## 3. 五层架构与 MVC 映射

```text
presentation  →  application  →  domain  →  data
      ↓              ↓             ↓
 infrastructure ─────┴─────────────┘
```

### 3.1 data：静态数据层

保存干员、技能、设施、阵营、规则版本和生成元数据。只提供只读查询，不保存一次模拟中的实时心情或布局。原始数据、标准化数据、运行时目录分离；生成物不得手工修改。

### 3.2 domain：领域层（Model）

定义实体和值对象：`Operator`、`Skill`、`Facility`、`Slot`、`Shift`、`Timeline`、`MoodState`、`ManualLedger`、`SimulationSnapshot`。实现心情速率、积分、进驻事件、换心情、闲置入宿和不变式；心情与技能结算的完整计算契约见 [`心情计算与技能结算.md`](心情计算与技能结算.md)。领域层不认识 JSON、React、Worker 或 HTTP。

对象关系：`Roster` 引用干员目录；`Schedule` 包含多个 `Shift`，每个班次引用设施布局和手动台账；`SimulationInput` 固定目录版本、排班、初始心情和规则设置；`SimulationRun` 在输入快照上产生分段 `Trajectory`、事件和结果索引。排班基线与模拟布局是不同对象，模拟布局不得反向写入基线。

### 3.3 application：应用层（Use Case / Controller 编排）

提供 `validateInput`、`simulate`、`curve`、`snapshot`、`detail`、`events`、`entryCandidates`、`idleCandidates`、`settingsSchema` 等用例。负责规范化输入、调用领域服务、建立不可变结果和结果投影；不实现具体 UI。

公开边界采用输入 DTO、结果 DTO、查询条件和领域错误映射。应用服务不暴露可变领域对象；命令改变排班草稿时返回新版本草稿，查询只读已发布的 `SimulationRun`。

### 3.4 infrastructure：基础设施层

提供目录加载、JSON 编解码、缓存、日志和外部模型适配。RIIC-Web 的 `BaseBlueprint`、`OperBoxEntry`、`ManualScheduleDraft` 必须在此转换为项目自己的输入 DTO。Worker、HTTP、NDJSON 均属于适配器，不得进入领域层。

适配器实现应用层定义的端口：`CatalogReader`、`SimulationResultStore`（首期可为内存实现）、`Clock`（仅显示时间格式化场景使用）和外部 DTO mapper。调用方无需知道适配器的文件、网络或缓存实现。

### 3.5 presentation：表现层（View）

Web UI 保留排班编辑、手动入宿、换心情设置、闲置入宿设置、时间轴回放、曲线和详情展示。View 不持有领域真源；Controller 将草稿提交给应用层并显示校验、计算状态和结果。

MVC 对应：领域模型与应用用例组成 Model/应用服务；Controller 接收用户动作、调用用例并管理页面草稿；View 渲染 DTO。组件只处理交互和显示格式，不实现规则。

## 4. 领域模块

| 模块 | 独占状态 | 主要职责 |
|---|---|---|
| 时间轴 | 班次、周期、执行点 | 生成班初和严格小于班末的 12h 内部执行点 |
| 布局 | 设施、位次、手动台账 | 导入布局、手动摆位、锁定、留洞和快照 |
| 心情 | 实时心情、速率、轨迹 | 十进制积分、边界钳位、红脸区间和曲线节点 |
| 名册 | 干员、练度、阵营、技能索引 | 稳定 ID、显示名与规则目录关联 |
| 自动化 | 换心情、闲置入宿 | 在执行点修改计算副本并记录事件 |
| 编排 | `SimulationInput`、执行顺序、结果 | 唯一协调跨模块写入和完整模拟生命周期 |
| 查询 | 结果投影 | 曲线、快照、速率账本、统计、候选和事件查询 |

领域命令接口草案：布局模块提供 `placeOperator`、`clearSlot`、`lockSlot`、`unlockAll`；自动化模块提供 `applyEntryEvents`、`applyIdleToDorm`；心情模块提供 `computeRate`、`integrateUntil`；编排模块提供 `simulate`。以上命令均作用于指定草稿或模拟副本，并通过新快照返回状态。具体 DTO 以 `协议格式.md` 为准。

模块只暴露只读快照与唯一命令入口。编排模块是跨模块协调的唯一位置；查询模块不得写入任何状态。

## 5. 一次模拟的标准流程

```text
规范化输入 → 校验目录与不变式 → 生成时间轴
→ 每个周期/班次/执行点重建原始布局
→ 继承实时心情
→ 换心情 → 闲置入宿 → 应用同刻手动心情指定
→ 重算最终布局速率 → 积分至下一个节点
→ 发布不可变轨迹、布局快照、事件和警告
```

手动入宿属于排班基线并随班次保存；自动换心情和自动入宿只作用于模拟副本。查询执行点时返回该点全部事件之后的状态。曲线在不同时间节点之间按规则插值，同一时刻用 `before/after` 表达离散跳变。

## 6. 扩展点与禁止事项

- 新技能：新增数据记录和技能策略，不在引擎中写干员名称分支。
- 新设施：新增设施目录、容量和速率策略，不修改通用布局流程。
- 新自动化：实现自动化策略接口，由编排器按明确优先级调用。
- 新输出：增加查询投影，不修改领域状态。
- 禁止 UI 直接执行心情公式、候选排序或修改模拟轨迹。
- 禁止通过中文显示名、数组位置或运行时对象身份关联持久化状态。

## 7. 验收标准

1. 相同规范化输入、规则版本和数据版本产生相同结果。
2. 手动布局、锁定区、留洞、换心情和闲置入宿逐位等价于领域规则。
3. 自动行为不回写原始排班；跨执行点只继承心情，不继承自动布局。
4. Worker、程序 API 和未来 HTTP 适配器调用同一应用层用例。
5. UI 可单独替换，核心可在无浏览器环境下测试。
6. 详见 `功能模块.md`、`协议格式.md` 和 `入宿逻辑.md`。
