# 测试与验收施工

## 1. 测试原则

测试以各 Module 的 Interface 为黑盒 seam，不依赖实现私有变量、数组布局或运行时对象身份。测试数据必须记录目录版本、规则版本和来源；涉及未知游戏事实时先查 `Kengxxiao/ArknightsGameData/zh_CN/gamedata/excel/` 并在 fixture 中记录依据。

## 2. 阶段循环

每个可执行阶段严格执行：

1. 根据当前源码和文档分析真实缺口。
2. 提交实现方案并等待用户同意。
3. 先在 `test/` 写黑盒测试，确认测试因缺实现而失败，不能跳过。
4. 实现最小范围代码。
5. 运行测试、静态检查和必要的协议/性能检查。
6. 测试通过后更新相关 `documents/`、必要时更新 `AGENTS.md` 和未来根 `README.md`。
7. 汇报实际运行的命令、结果、未运行项和残余风险。

纯文档阶段没有可执行逻辑，不创建伪测试；本阶段采用 Markdown 结构、本地链接、术语、协议示例、规则唯一真源和计划/现状措辞检查。

## 3. 测试分层

| 目录 | 黑盒对象 | 必测内容 |
|---|---|---|
| `test/contracts` | 协议/DTO | 版本、十进制字符串、错误信封、未知字段和限制 |
| `test/data` | `CatalogReader` | 上游版本、索引、引用、只读和未知事实拒绝 |
| `test/domain` | 领域 Interface | 心情积分、时间边界、28 条入宿不变量、确定性 |
| `test/application` | 用例 Interface | revision、查询只读、结果发布、错误映射 |
| `test/adapters` | Worker/API/映射 Adapter | 取消、过期响应、RIIC-Web 转换、序列化 |
| `test/ui` | 用户可见流程 | 设置、手动入宿、换心情、闲置入宿、回放和错误 |

## 4. 领域验收矩阵

至少覆盖：0/12/班末时间点、严格小于班末的内部换班、同刻 before/after、心情钳位、十进制定点、手动台账优先级、留洞不左移、锁定区空位、最大合格住户、相等也换、被换出者不再入队、黑名单只拦进入、自动布局不回写基线、无候选仍记录换班标记、重复输入结果一致。

## 5. 文档验收

提交文档前执行：

- Markdown 标题层级、代码围栏和表格结构检查；
- 所有相对链接存在且指向正确文档；
- `MoodSimulationRequest`、设置 DTO、查询信封与协议真源一致；
- “已定规则/设计契约/待实现/待核实”措辞没有混淆；
- Module、Interface、Seam、Adapter、Depth、Leverage、Locality 术语用法一致；
- 施工文档未重复定义 `入宿逻辑.md` 的完整规则；
- 未把参考项目代码或二手资料写成当前仓库事实。

## 6. 发布与 Git 门禁

测试或文档检查未执行、失败或环境缺失必须明确报告。阶段完成时提醒用户决定是否更新受影响文档、`AGENTS.md`、未来 `README.md`，以及是否 Git 初始化、暂存、提交；提交前列出仓库边界和文件清单，不擅自推送。
