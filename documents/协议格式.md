# 心情模拟协议

## 1. 定位与边界

本协议服务于“按班次展示干员心情变化，并执行换心情、闲置入宿和手动入宿设置”的模拟核心。它不是 RIIC-Web 全站协议，不包含数据库、求解器任务、工作区同步、遥测或质量回归。

RIIC-Web 的页面模型由基础设施适配器转换为本协议的规范化输入。Web Worker 是首要运行适配器；程序 API 复用同一应用层用例。本文中的接口在源码完成前均属于设计契约。

## 2. 通用规则

- `protocolVersion` 为整数，首版为 `1`。
- 稳定关联使用 `operatorId`、`facilityId`、`slotIndex`、`cycleIndex`、`shiftIndex`，不得使用显示名。
- 数值在协议中使用十进制字符串，例如 `"23.875"`；UI 可转换为图表数字。
- 时间使用从模拟起点开始的 `offsetHours`；`displayStartTime` 只影响显示。
- 区间统一为左闭右开 `[start, end)`。
- 未知枚举值、缺少必需字段和越过限制的输入拒绝；未知可选字段可忽略。
- 错误由 `code`、`message`、`path`、`details`、`retryable` 组成，UI 不得按中文消息分支。

## 3. 输入模型

`MoodSimulationRequest` 包含：

```json
{
  "protocolVersion": 1,
  "ruleVersion": "mood-v1",
  "catalogVersion": "catalog-2026-10",
  "layout": { "facilities": [] },
  "roster": [],
  "shifts": [],
  "initialMoods": {},
  "settings": {},
  "displayStartTime": "00:00"
}
```

输入必须包括规范化设施布局、干员名册与练度、班次、手动布局/台账、初始心情和模拟设置。设置包括周期数、换心情、闲置入宿、黑名单、锁定位置数及相关目标。未提供初始心情才使用明确记录的默认值。

规范化请求字段约束：

| 字段 | 类型 | 约束 |
|---|---|---|
| `protocolVersion` | integer | 必填，当前为 `1` |
| `ruleVersion` / `catalogVersion` | string | 必填并随结果回显 |
| `layout.facilities[]` | array | 稳定 `facilityId`、类型、等级、启用状态和位次 |
| `roster[]` | array | 稳定 `operatorId`、练度及目录引用 |
| `shifts[]` | array | 顺序稳定、时长为十进制小时、含基线设施分配和台账 |
| `initialMoods` | map | `operatorId → decimal string`，缺项使用明确默认并警告 |
| `settings` | object | 周期、换心情、闲置入宿、锁定和黑名单配置 |
| `displayStartTime` | `HH:mm` | 可选，仅用于显示，不参与积分 |

### 3.1 设置 DTO

```json
{
  "cycles": 3,
  "entry": {
    "enabled": true,
    "shifts": {
      "shift_1": { "enabled": true, "mode": "specified", "targetOperatorId": "op_002", "waitForFull": false, "restorePosition": false }
    }
  },
  "idle": {
    "enabled": true,
    "lockPositionCount": 0,
    "blacklist": [],
    "overrides": {}
  }
}
```

`mode` 为 `specified`、`previous` 或 `auto`。逐人参与开关不属于设置；阻止自动入住使用全局黑名单。`overrides` 只允许协议定义的候选目标/禁用规则，不得改变候选算法。

`lockPositionCount` 的默认值和完整规则见 [`入宿逻辑.md` §9](入宿逻辑.md#9-锁定位置)。示例使用默认不启用锁定区的值；手动台账与闲置入宿开关仍独立生效。

## 4. 操作

| 操作 | 作用 |
|---|---|
| `capabilities` | 返回版本、数据目录、规则、支持操作和限制 |
| `settingsSchema` | 返回设置字段、默认值、约束和可选项 |
| `validateInput` | 返回字段级错误和警告 |
| `simulate` | 执行完整模拟并发布不可变 `simulationId`/`revision` |
| `curve` | 查询一个或多个干员的关键曲线节点 |
| `snapshot` | 查询指定时刻的布局和全员心情 |
| `detail` | 查询指定干员指定时刻的速率账本 |
| `events` | 查询换心情、入宿、跳过和内部换班事件 |
| `entryCandidates` | 查询换心情的合法目标 |
| `idleCandidates` | 查询自动入宿候选及合法目标 |
| `cancel` | 取消尚未发布结果的请求 |

手动入宿通过修改排班草稿/手动台账后重新调用 `simulate`，不直接修改已发布模拟。

## 4.1 贯穿式调用示例

请求：

```json
{
  "id": "req_01",
  "type": "simulate",
  "input": {
    "protocolVersion": 1,
    "ruleVersion": "mood-v1",
    "catalogVersion": "catalog-2026-10",
    "layout": { "facilities": [{ "facilityId": "dorm_1", "facilityType": "dormitory", "level": 5, "enabled": true, "slots": ["op_001", null, null, null, null] }] },
    "roster": [{ "operatorId": "op_001", "elite": 2, "level": 30 }, { "operatorId": "op_002", "elite": 2, "level": 30 }],
    "shifts": [{ "shiftId": "shift_1", "durationHours": "12", "facilityAssignments": {} }],
    "initialMoods": { "op_001": "20", "op_002": "8" },
    "settings": { "cycles": 2, "entry": { "enabled": false, "shifts": {} }, "idle": { "enabled": true, "lockPositionCount": 0, "blacklist": [], "overrides": {} } },
    "displayStartTime": "08:00"
  }
}
```

成功回执：

```json
{ "id": "req_01", "type": "result", "simulationId": "sim_01", "revision": "rev_01", "totalHours": "24", "operatorIds": ["op_001", "op_002"], "warningCodes": [] }
```

后续以同一 `simulationId`/`revision` 请求 `curve`、`snapshot`、`detail` 或 `events`。设置修改必须重新 `simulate`，不得在已发布结果上应用设置变更。

## 5. 模拟生命周期

`simulate` 返回 `simulationId`、`revision`、总时长和结果索引。后续查询必须携带二者；输入变化必须产生新的 `revision`。Worker 默认只保留最近一次模拟，过期响应不得覆盖当前结果。结果发布后不可修改，查询只生成投影。

## 6. 曲线模型

曲线由关键节点组成，不提供固定分钟采样：

```json
{
  "operatorId": "op_001",
  "interpolation": "linear-between-distinct-times",
  "sameTimePolicy": "before-after-jump",
  "points": [
    { "offsetHours": "12", "phase": "before", "mood": "8.5", "eventIds": [] },
    { "offsetHours": "12", "phase": "after", "mood": "24", "eventIds": ["evt_17"] }
  ]
}
```

不同时间节点之间允许线性插值；同一时间的 `before`/`after` 是事件跳变，不能插值。心情始终钳位在 `[0,24]`。

## 7. 快照、明细与事件

`snapshot` 返回 `offsetHours`、`cycleIndex`、`shiftIndex`、事件之后的全员心情、当前设施位次和布局来源（`baseline` 或 `simulation`）。`detail` 返回 `consume`、`recover`、`net` 及逐项贡献账本。`events` 返回稳定事件 ID、时间、类型、操作者、目标、原位次、原因和执行顺序。

结果投影还可包含每班最低心情、平均净消耗、红脸区间、周期末心情、稳定性、首次红脸时间、闲置候选和警告。

成功查询信封：

```json
{ "id": "req_02", "type": "snapshot", "simulationId": "sim_01", "revision": "rev_01", "data": { "offsetHours": "12", "phase": "after", "moods": { "op_001": "18", "op_002": "10" }, "layoutSource": "simulation", "facilities": [] } }
```

字段级验证失败：

```json
{ "id": "req_03", "type": "error", "error": { "code": "VALIDATION_FIELD_INVALID", "message": "Invalid input", "path": "shifts[0].durationHours", "details": { "expected": "positive decimal string" }, "retryable": false } }
```

## 8. Worker 消息

Worker 只负责消息校验、调用应用层、保存最近快照、关联请求/取消和序列化错误，不实现规则：

```text
request:  { id, type: "simulate", input }
response: { id, type: "result", simulationId, revision, result }
request:  { id, type: "curve", simulationId, revision, operatorIds, range }
response: { id, type: "curve", simulationId, revision, curves }
```

错误类型包括 `VALIDATION_*`、`CATALOG_*`、`SIMULATION_*`、`QUERY_*`、`PROTOCOL_*` 和 `CANCELLED`。

每个请求 ID 在 Worker 生命周期内唯一。`cancel` 指向 `requestId`；取消完成后不得再发送该请求的成功响应。`simulationId` 标识不可变结果，`revision` 标识调用方当前输入代次，二者不得混用。

## 9. 限制与能力

最大周期、班次数、干员数、设施数、请求体积、Worker 超时和缓存数量由 `capabilities` 返回。超过限制返回 `VALIDATION_LIMIT_EXCEEDED`，不得静默裁剪。

## 10. 适配器边界

RIIC-Web 的 `BaseBlueprint`、`OperBoxEntry`、`ManualScheduleDraft` 只能在适配器中转换；核心不依赖这些页面类型。Web UI 负责控件、草稿、防抖、播放、颜色、本地化和设置持久化；核心负责默认值、校验、候选、规则和结果。

## 11. 版本与复现

结果记录实际使用的 `protocolVersion`、`ruleVersion`、`catalogVersion` 和规范化输入摘要。新增可选字段不升主版本；删除字段、改变语义或默认值必须升主版本。相同输入和版本必须产生相同结果。

发布前设计记录：2026-10-16 用户确认将默认锁定数从 5 改为 0。当前尚无已发布的 Worker/程序 API 协议实现，故此调整纳入首版 `1` 的设计；发布后的默认值变更仍严格遵守上述主版本规则。
