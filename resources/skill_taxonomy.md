## 0. 目的

让「导入新干员技能」从**人肉读描述 + 改代码**，变成**认模板 + 填参数**；
并且**永远不会悄悄漏掉一条心情技能**——漏掉会变成生成时的硬报错。

**当前状态**：242 个 clause 全部命中模板，755 条 buff 全部有建模地位，未归类 **0**。

## 1. 六条正交轴

任意一条技能 = 六轴上的一个点。**模板 = 真实数据里出现过的 (B,C,D,E,F) 组合**，给稳定 ID。

| 轴 | 含义 | 取值 |
|---|---|---|
| **A 建模地位** | 要不要算 | `A1` 心情速率 / `A2` 心情事件 / `A3` 心情当条件 / `A4` 非心情 |
| **B 作用域** | 作用到哪个空间 | `B0` 自身设施 / `B1` 同设施 / `B2` 跨设施 / `B3` 宿舍 / `B4` 全局规则 |
| **C 作用对象** | 作用到谁 | `C1` 自身 / `C2` 同设施全体 / `C3` 同设施其他 / `C4a` 宿舍全体 / `C4b` 宿舍单体 / `C5` 条件筛选 / `C6` 全基建 |
| **D 效果** | 改哪个量 | 心情 5 族 / 产出 8 族 / 变量 / 特殊订单 / 设施计数 |
| **E 数值形态** | 参数长什么样 | `E1` 定值 / `E2` ×等级 / `E3` ×设施数 / `E4` ×人数 / `E5` 阈值 / `E6` 池 / `E7` 集 / `E8` 倍率 / `E9` 解锁链 |
| **F 叠加规则** | 多来源怎么合 | `F1` 求和 / `F2` 同种取最高 / `F3` 跨干员取最高 / `F4` 互斥 / `F5` 替换 / `F6` 池 / `F7` 归零优先 |

> **「规则修饰」不单独成族**（已按决策并入 **F 轴**）：描述里的「同种效果取最高 / 特殊比较规则 /
> 归零 / 恒定 / 除以 / 优先生效」只改**怎么合**，不改**改什么**，因此属于轴 F。

### 1.1 一条铁律：模板挂在 clause（子句）上

游戏一个 buff 常含多个子句，子句可属不同族：

| buff | 子句 ① | 子句 ② |
|---|---|---|
| `trade_cost&bd2[000]` 跋山涉水 | 贸易站全体心情消耗 −0.1（`M05`/`A1`） | 每有 10 点人间烟火再 −0.01（`M05`/`A1`，条件槽空） |
| `dorm_rec_all&oneself[011]` 挣脱 | 自身 +0.1（`M10`） | 除自身外全体 +0.1（`M08`，`exclude_self=true`） |
| `control_mp_lonely[000]` 公事公办 | room1 +0.1（`M02c`） | 扩散白名单（同一子句的 `spread` 参数） |

所以：`moods_skills.txt` 是 **clause 级**（建模用），`skills_registry.txt` 是 **buff 级**（防漏用）。

### 3.1 `M17` 是台账抓出来的真漏网

正是**台账（755 行全覆盖）**兜住的第一条。引擎尚未实现，但已被强制登记。

## 5. 已拍板的口径与规则（决策记录）

### 5.1 巫恋「低语」= 全体**含自身**

官方原文：「进驻贸易站时，当前贸易站内其他干员提供的订单获取效率全部归零…同时**全体**心情每小时消耗 +0.25」。
「全体」= 当前贸易站内全体干员（含巫恋自己）。

- 数据改动：`trade_ord_vodfox_000` 的 `family` 由 `room_others` 改为 `room` → 映射到 `FACILITY_CONSUME`（`M05`，`include_self=true`）。
- 影响：巫恋自身净消耗由 `1 − 0.1 − 0.25(裁缝α) = 0.65` 变为 `0.65 + 0.25(低语) − 0.25 = 0.65`。
- `M06`（不含自身）**保留但当前无使用者**——将来若出现真正的「其他干员」类技能直接用它。

### 5.2 `M02b` 取最高（实现）

官方术语 `cc.c.sui2_1`：「在**公事公办**，**孤光共照**，**巴别塔之帜**提供的『其他设施』每小时心情恢复值中**取最高**生效」。

- 实现口径：**同一名干员自己的 clause 先求和，再跨干员取 max**（与中枢减免一致）——因为「取最高」约束技能之间，不约束同一技能的分句之间。
- 数据：三条技能的子句带 `max_group=room2_recover`；`rules._work_recovery` 按 group 取最高。
- 例：玛恩纳 + 重岳 + 维什戴尔同在中枢，制造站目标 = `max(0, 0.05, 0.1) = 0.1`（旧实现求和得 0.25 → 高估）。

### 5.3 `M02c` 玛恩纳扩散（实现）

官方术语 `cc.c.skill`「部分技能」列出 **15 条**白名单（`control_mp_cost_000`~`014`：左膀右臂、S.W.E.E.P.、
零食网络、清理协议、替身、必要责任、护卫、小小的领袖、独善其身、笑靥如春、金盏花诗会、捍卫之道、
博识生手、点滴关照、总工程师）。玛恩纳在中枢时，**这 15 条技能自己的回复值额外作用到 room2（其他设施）
内处于工作状态的干员**。

- 数据：`公事公办` 带 `spread=cc.c.skill`；白名单 id 表烧进 `skills_data.SPREAD_SKILL_IDS`（运行时无需上游仓库）。
- 引擎：`rules._reaches` / `_spread_active`——扩散提供者**红脸（心情 ≤ 0）时扩散失效**。
- 例：中枢 `[玛恩纳, 陈]` → 制造站目标回复 `0.05`（玛恩纳的独善其身扩散而来）；无玛恩纳则 `0`。

### 5.4 `untranslated` → `partial`（模板确定 + 条件槽空 → 保留效果骨架）

| 字段 | 语义 |
|---|---|
| `partial=true` | 模板已确定，但**某个条件槽是空的**（原 `status=complex`） |
| `partial_mode="apply"` | 子句的 `value` **本身无条件成立**，缺失的只是额外加成/倍率 ⇒ **按骨架生效** |
| `partial_mode="hold"` | 子句的 `value` **本身以缺失条件为前提** ⇒ 保留模板与骨架，但**仍不生效** |

判定规则（`scripts/classify_skills.py`）：条件文本**为空**或含「**额外**」⇒ `apply`；其余（每有 / 每个 / 阈值 / 共事）⇒ `hold`。

**安全性设计**：`partial_mode` 只在「老逻辑本来就不生效」的子句上放宽，老逻辑已能翻译的子句（`COND_MARKERS` /
`FACTION_COUNT_SKILLS` / `COOP_COND` 命中项）一律不受影响——**只放宽，不收紧**。

结果：不生效子句 **37 → 31**，其中 6 条重新生效且都是正确的：

| 子句 | 技能 | 值 | 为什么 `apply` 是对的 |
|---|---|---|---|
| `dorm_rec_single&tag_000#1` | 罗德岛隐秘队 狩猎好帮手 | 0.55 | 0.55 是基础恢复，`+0.45` 才是条件额外 |
| `dorm_rec_single_P_000#1` | 黑 沏茶 | 0.55 | 同上（目标是锡兰时 +0.45） |
| `dorm_rec_single_P_001#1` | 特米米 烤肉大师 | 0.55 | 同上（嘉维尔） |
| `dorm_rec_single_P_002#1` | 深靛 毒剂师之友 | 0.55 | 同上（蓝毒） |
| `dorm_rec_single_power_000#1` | 寒檀 降生于冰寒 | 0.55 | 同上（萨米干员） |
| `dorm_rec_single_power_001#1` | 新约能天使 圣城趣事通 | 0.55 | 同上（拉特兰干员） |

反例（正确地保持 `hold`）：孤光共照 `#2`「每有 20 点人间烟火 +0.05」——它的 `value` **本身**以计数器为条件，
若无条件计入会让重岳单人从 0.05 高估到 0.10，因此保持不生效。

### 5.5 设施集合改为引用官方术语

## 6. 导入新干员技能的流程

```
新干员（或旧干员新技能）
  │
  ├─ 1. 更新 resources/operators.txt（干员↔buff 映射 + 解锁）
  │
  ├─ 2. 跑 scripts/classify_skills.py --agd <仓库>
  │       ├─ 每个 buff 落进 resources/skills_registry.txt（755 → 756…）
  │       └─ 未命中模板 → template_id = "??" → 校验失败并打印清单
  │
  ├─ 3. 看校验输出：
  │       ├─ 命中心情模板（M01~M17）→ 在 moods_skills.txt 加 clause 行，填 template_id + params
  │       ├─ 落在 X 族 → 无需动作（登记完事，不影响计算）
  │       └─ 未命中  → 人工判定：是新模板？还是旧模板的新参数？补进 skill_templates.py
  │
  ├─ 4. 跑 scripts/generate_skills_data.py → 重写 mood_soc/skills_data.py
  │
  └─ 5. 跑 .venv/Scripts/python.exe -m unittest discover -s tests
```

**机器保证**：`classify_skills.py --check` 断言
①`moods_skills.txt` 每行的 `template_id` 都在注册表里；
②`skills_registry.txt` 行数 == 上游 buff 总数；
③无 `tier=??` 行。任一不满足即退出码 1。

## 7. 已知缺口（下一步）

1. **`M09` 的 `per_target_bonus`**：沏茶/烤肉大师等的「若目标是 X，额外 +0.45」尚未实现（基础 0.55 已生效）。
2. **`M15a` 心情互换**（菲亚梅塔 患难之交）、**`M15b` 触发式恢复**（棘刺 爆炸艺术）：骨架已登记，引擎未实现。
3. **`M17` 元修正**（摩根 头号陪练）：需「修改他人技能效果」的机制。
4. **`M12` 的条件槽**：刺玫/净化呼吸/头号陪练类条件尚有部分靠 `COND_MARKERS` 文本匹配，可逐步转为模板参数。
5. **per-count 变量的数值化**：`X09` 的 26 种变量（人间烟火等）尚未参与计算，导致依赖它们的
   加成子句只能 `hold`（如孤光共照 `#2`、跋山涉水 `#2`）。
6. **`per_count` 轴 E 的展开**：柔和微光「每有 1 间发电站」、死前必做清单「宿舍每级」、
   独处「每有 1 名其他干员」这类**可数条件**其实能直接算，目前一并 `hold`，偏保守。
